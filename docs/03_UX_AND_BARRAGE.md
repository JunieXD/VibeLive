# FakeLive 交互、控制台与屏幕弹幕规格

> 文档状态：从零设计基线  
> 适用范围：Windows 桌面端  
> 优先级说明：`P0` 为黑客松必须跑通，`P1` 为首个可用版本，`P2` 为最终产品扩展  
> 本文取代旧版“竖向直播评论窗”交互。FakeLive 的核心显示面是覆盖目标显示器的横向屏幕弹幕层。

## 1. 体验目标

FakeLive 要让一个人在游戏、看视频或使用桌面时，感受到一群有稳定性格的 AI 观众正在看、听和回应自己。用户看到的不是聊天机器人窗口，而是像直播间一样自然起伏的弹幕：平静时可以安静，也可以聊烂梗；击杀、失误、反转等时刻会突然热闹；主播说话后，某些观众会接话、质疑、安慰或复读。

交互设计遵循以下原则：

1. **不挡操作**：直播中弹幕层默认完全鼠标穿透，不改变下层游戏或软件的输入。
2. **随时能停**：暂停、隐藏、清屏、解锁和停止直播都必须有不依赖弹幕层点击的入口。
3. **先说明再上传**：首次向云端发送截图或转写前，明确展示发送内容、用途和停止方式。
4. **状态可解释**：用户必须知道当前是否正在采集画面、监听麦克风、调用 AI，以及是否处于降级状态。
5. **热闹不等于失控**：弹幕密度、位置、速度和内容边界始终受用户上限和安全策略约束。
6. **不像调试器**：正常使用界面不展示 prompt、Token、原始响应、内部推理或技术管线名。
7. **不是营销页**：启动即进入可操作的直播控制台，不设置落地页、巨大宣传标题或装饰性卡片墙。

## 2. 用户可见界面

最终产品包含五类可见界面。黑客松完整实现首次启动、控制台和弹幕层，并提供简化的独立恢复窗与托盘核心命令。

| 界面 | 职责 | 黑客松 | 最终产品 |
| --- | --- | --- | --- |
| 首次启动向导 | 云端告知、连接检查、设备选择、人格和弹幕校准 | P0 | P0 |
| 直播控制台 | 开播前设置、直播中状态、暂停/清屏/停止 | P0 | P0 |
| 屏幕弹幕层 | 透明置顶、点击穿透、弹幕渲染 | P0 | P0 |
| 独立恢复窗 | 在弹幕层锁定或异常时恢复控制 | P0，可简化 | P0 |
| 托盘菜单 | 后台状态、显示控制台、暂停、解锁、停止 | P0 | P0 |

### 2.1 控制台的信息架构

控制台采用安静、紧凑的直播工具布局。左侧为一级导航，右侧为当前任务面；窄窗口下改为顶部标签，不把每一组设置做成嵌套卡片。

一级页面：

- **开播**：来源预览、麦克风电平、背景说明、人格摘要和开始直播；P1 增加扬声器测试。
- **直播中**：运行状态、时长、当前热度、活动人格数量，以及暂停、清屏、隐藏和停止。
- **弹幕**：字体、颜色、描边、速度、密度、显示区域、固定弹幕和保护区。
- **AI 观众**：人格包、单个人格启停、基础热闹度、爆点上限、冷场策略。
- **内容**：屏蔽词、语气强度、安全选项、近似复读控制。
- **设备与隐私**：画面来源、弹幕目标显示器、麦克风、扬声器、云端发送说明和数据清理。
- **高级**：观察决策频率、每秒请求上限、实际并发上限、观察窗口和诊断记录导出。默认折叠，避免普通用户面对 32 路请求参数。

## 3. 首次启动向导

首次启动向导是一次可返回、可重新执行的六步流程。除云端告知外，每一步都可稍后从设置页修改。

### 3.1 第一步：云端处理告知

必须在第一次发送真实画面或转写之前显示，不得用预勾选复选框代替同意。

展示内容：

- 会发送：用户选择来源的近期截图、近期主播语音转写、主播主动填写的背景和人格上下文。
- 不默认保存：本地不落盘保存原始截图和原始音频；诊断日志不写 API Key、图片正文或完整转写。
- 处理方：StepFun `step-explore` 云端接口。
- 停止方式：暂停直播会立即停止新采集和新请求；停止直播会关闭采集轨道并取消在途请求。
- 未经服务条款确认，不承诺云端“绝不留存”；界面应链接当时有效的服务说明。

主操作文案：`同意并继续`。次操作文案：`退出`。

### 3.2 第二步：连接检查

Control 只配置一次开发者自有 StepFun Key，同时分别展示 Step-explore 与 StepAudio 健康状态，但不直接放置 API Key 文本框。开发者点击`添加/更换密钥`后，Main 创建一次性的隔离 `KeyEntry` 小窗：`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、DevTools 关闭、禁止导航和网络，仅允许把一次提交通过窄 preload 送给 Main。提交后立即清空字段并销毁窗口；JavaScript 内存不承诺可逐字节抹除，因此不把它描述成硬件级安全输入。

已有密钥时 Control 只显示`已配置`、创建时间和测试/删除按钮，永远不能读取或回显原文。Main 从安全存储读取 Key 后执行以下检查：

1. 认证是否成功。
2. 文本请求是否可用。
3. 图片消息格式是否通过真实探针验证。
4. SSE 是否能收到内容并支持取消。
5. StepAudio WebSocket 是否能鉴权、完成 `session.update` 并安全关闭。

黑客松可以把图片/SSE探针作为开发前置命令，但产品界面仍需提供明确的连接状态。未验证的接口能力必须显示为`待验证`，不能用“已连接”暗示多模态、并发和流式都已可用。

状态文案：

- `AI 服务可用`
- `密钥无效，请检查后重试`
- `文字请求可用，图片格式仍待验证`
- `StepAudio 实时语音可用`
- `Step-explore 可用，StepAudio 尚未开通`
- `请求过快，正在等待服务恢复`

### 3.3 第三步：选择画面来源和弹幕目标

**画面来源**和**弹幕目标**是两个独立概念：

- 画面来源：被 AI 观察的屏幕或应用窗口。
- 弹幕目标：承载透明弹幕层的显示器。

界面不得把二者合并成一个“屏幕”选择器。默认可根据用户选择做合理联动，但必须可单独修改。

画面来源选择器显示实时缩略图、应用名、窗口标题或显示器编号。弹幕目标显示器用编号、分辨率、缩放比和物理位置标识，例如：`显示器 2 · 2560×1440 · 125% · 右侧`。

选择 FakeLive 自身窗口时应禁止开始，并提示：`不能把 FakeLive 作为画面来源`。采集实现必须排除控制台、恢复窗和弹幕层，避免 AI 反复观看自己生成的内容。

### 3.4 第四步：选择声音设备

麦克风区域包含：

- 标准 Windows 输入设备选择器。
- 10 秒实时电平条。
- `测试麦克风`命令和转写预览。
- 当前采样状态，不显示或保存完整历史转写。
- 设备断开后的重新选择入口。

P1 扬声器区域包含：

- 标准 Windows 输出设备选择器。
- `播放测试音`命令。
- 输出设备记忆。

扬声器选择只用于应用测试音、提示音或未来监听，不等于采集系统声音。黑客松 P0 不把扬声器选择或系统声音理解作为开播前提。

完整产品体验需要麦克风。为了故障恢复，设备不可用时可明确进入`仅画面模式`，但不能伪装为完整模式。首次设置中应优先帮助用户修复麦克风，而不是默认跳过。

### 3.5 第五步：选择 AI 观众

默认展示人格包而不是 32 个并发开关：

- `热闹游戏房`：质疑、乐子、技术、老粉和新人混合。
- `6657 玩机器风格`：抽象梗、反串和复读倾向更高，但仍遵守安全底线。
- `新人友好`：解释、鼓励和提问更多，攻击性更低。
- `温和陪伴`：回应主播和安慰更多，爆发更克制。
- `竞技嘴硬局`：质疑、指挥和赛后诸葛亮更多。
- `自定义`：逐个人格启停、调整权重和保存为新包。

普通设置使用两个可理解参数：

- `基础热闹度`：安静、自然、热闹。
- `爆点上限`：克制、明显、满场。

高级设置才暴露基础活动人数、最大并发、每人格冷却和观察窗口。界面应说明“启用 32 位观众”不等于“任何时刻同时发出 32 条弹幕”。

### 3.6 第六步：弹幕校准和恢复测试

校准态暂时关闭点击穿透，显示测试弹幕、轨道边界和当前显示区域。P0 用户可以：

- 调整速度、密度和显示面积，使弹幕避开主要操作区域。
- 触发一次模拟爆点，确认峰值密度可接受。
- 按一次紧急解锁快捷键，确认系统级快捷键未冲突。
- 从托盘执行一次`解锁弹幕层`。
- 点击独立恢复窗中的解锁按钮。

P1 校准再增加矩形保护区、字号/颜色/透明度和滚动/顶部/底部三种弹幕的预览。

三个恢复路径全部通过后，才把弹幕层切换为默认穿透态。校准失败不阻止保存其他设置，但不能进入直播穿透态；用户只能留在校准态修复，或退出。

## 4. 开播前控制台

开播页应让用户在一个视图里回答五个问题：AI 看哪里、弹幕飘哪里、听哪个麦克风、这群观众是谁、能否安全开始。

推荐布局：

```text
┌ 来源预览 ─────────────────┬ 直播设置 ────────────────┐
│ 当前选择的真实画面        │ 麦克风 [设备]  ▂▅▇       │
│ 不叠加弹幕和调试框        │ (P1) 扬声器 [设备] [测试] │
│                           │ 主播称呼 [________]       │
│                           │ 背景/游戏 [___________]   │
├ 状态列 ──────────────────┤ 人格包 [热闹游戏房]       │
│ 画面 / 麦克风 / AI / 恢复 │ 冷场策略 [自然冷场|持续热闹]│
└───────────────────────────┴────────────── [开始直播] ┘
```

`开始直播`的必要条件：

- 已完成云端告知。
- 已选择合法且仍存在的画面来源。
- 已选择有效的弹幕目标显示器。
- 全局快捷键、托盘和独立恢复窗三条恢复路径都已实测可用。
- API Key 已安全配置，且基本连接检查通过。
- 麦克风正常，或用户主动确认进入`仅画面模式`。

开始时先创建会话并打开画面轨道，然后按模式分支：

- `完整模式`：打开麦克风轨道，启动已选 `SpeechProvider`，通过音频 ready 检查。
- `仅画面模式`：不请求麦克风权限、不创建 audio track、不启动 ASR，观察快照的 `transcripts` 为空并持续显示降级标记。

两条分支随后都启动人格引擎、创建弹幕层、确认三条恢复路径与点击穿透，最后进入直播中。第一版完整模式默认使用已明确告知音频上传的 StepAudio 2.5 WebSocket，本地 Runtime 仅是未来可选 Provider；任一环节失败必须回滚该分支已打开的资源。

## 5. 直播中控制台

直播中页面优先展示运行状态和紧急命令，不展示大量可调表单。

### 5.1 常驻状态

- 直播时长。
- 当前画面来源和弹幕目标。
- 画面采集：正常 / 来源断开 / 已暂停。
- 麦克风：正常 / 静音 / 断开 / 仅画面模式。
- AI 服务：正常 / 限流 / 部分人格降级 / 不可用。
- 当前热度：冷场 / 日常 / 爆点。
- 活动人格：例如`8 / 32`，其中前者是当前参与决策数，不是正在显示的弹幕数。
- 待显示弹幕数；超过安全阈值时显示`正在丢弃过期弹幕`而不是无限排队。

### 5.2 一级命令语义

| 命令 | 用户预期 | 必须发生的系统行为 |
| --- | --- | --- |
| 暂停 | 暂时停止被观察 | 停止画面/麦克风新采样，取消在途 AI 请求，丢弃等待队列；恢复后只使用新上下文 |
| 继续 | 从此刻重新开始 | 重新打开或恢复采集，不补发暂停期间的画面与弹幕 |
| 清屏 | 立刻移除眼前文字 | 清除已显示和待显示弹幕；采集和 AI 继续运行 |
| 隐藏弹幕 | 暂时不看弹幕 | 隐藏弹幕层但直播继续；隐藏期间生成的弹幕不积压，直接丢弃 |
| 显示弹幕 | 恢复当前直播 | 只显示恢复之后进入调度的弹幕 |
| 解锁 | 调整弹幕层 | 关闭穿透并进入校准态；AI 可继续，但默认暂停弹幕调度 |
| 停止直播 | 立即结束 | 不弹确认框；终止采集、ASR、SSE、队列和弹幕层，返回开播页 |

暂停是隐私操作，不只是视觉暂停。清屏和隐藏不是暂停。停止直播不应弹出阻塞式二次确认，避免紧急情况下多一步操作；误触风险通过按钮位置、图标和快捷键设计解决。

## 6. 弹幕层行为

### 6.1 窗口属性

弹幕层必须满足：

- 无边框、透明背景、无任务栏图标。
- 始终置顶，但不抢下层应用焦点。
- 直播态鼠标穿透；校准态可交互。
- 尺寸严格匹配目标显示器工作坐标。
- 每个显示器使用独立窗口，而不是跨多屏的一张巨型原生窗口。
- 排除自身采集；Windows 支持能力不足时至少通过选择来源和合成链路避免自反馈。
- 关闭或崩溃不会阻断控制台和全局恢复命令。

弹幕层正常状态不显示面板、背景、房间头部、AI 标签、在线人数或调试状态。用户只看到文字弹幕。

### 6.2 状态机

```text
关闭
  -> 校准态（可点击，显示边界）
  -> 穿透态（直播默认）
  -> 暂停态（画面冻结或隐去，禁止新弹幕）
  -> 隐藏态（窗口不可见，不积压）
  -> 紧急解锁态（可点击，显示最小恢复条）
  -> 关闭
```

弹幕层状态和直播会话状态不能混成一个布尔值。例如隐藏弹幕层时，会话仍可能是`直播中`；暂停会话时，弹幕层仍可以显示`已暂停`的短暂状态提示后隐去。

### 6.3 轨道和碰撞

P0 轨道系统支持：

- 从右向左滚动。
- 同轨弹幕不会追尾或重叠。
- 根据字体真实测量宽度，不按字符数估算。
- 窗口缩放、显示器分辨率变化后重新计算轨道。
- 只在用户选择的显示区域内分配轨道。
- 高峰时优先丢弃低优先级、过期或完全重复弹幕，而不是强行叠放。

P1 增加顶部/底部固定弹幕、矩形保护区和近似重复抑制；这些能力可以预留领域类型，但 P0 不显示无效设置。

每条弹幕进入渲染前都要带`showAt`和`expiresAt`。到达`expiresAt`后即使轨道刚空出来也不得显示，避免三杀已经过去十秒才出现“？？？”。

### 6.4 密度控制

密度由四层共同限制：

1. 用户选择的基础热闹度。
2. 用户选择的爆点上限。
3. 导演 AI 给出的当前热度和参与人格数量建议。
4. 本地调度器的硬上限、轨道容量、TTL 和显示区域。

导演 AI 只能在用户硬上限内增加活动人格，不能直接绕过调度器塞满屏幕。普通事件不应触发整屏弹幕潮；同一爆点必须有事件冷却，防止一段击杀回放或结算画面反复触发。

建议初始默认值，均需真实桌面测试后校准：

| 参数 | 黑客松默认 | 备注 |
| --- | ---: | --- |
| 滚动轨道占屏高度 | 55% | 避开底部字幕和顶部状态栏 |
| 常态屏幕同时可见 | 6–10 条 | 取决于分辨率和字号 |
| 普通事件 5 秒新增 | 3–8 条 | 由人格自然返回，不强行补齐 |
| 爆点 5 秒新增 | 12–24 条 | 不代表 32 路都必须发言 |
| 单条最大显示时长 | 8 秒 | 超时清理 |
| 事件反应 TTL | 5 秒 | 待真实延迟探针验证 |

### 6.5 保护区

P1 用户可以建立至少一个矩形保护区并按游戏保存预设；最终产品支持多个、命名、导入和按应用自动切换。P0 只通过整体显示区域避开主要操作区域，不展示尚未实现的保护区编辑器。

保护区规则：

- 固定弹幕不得覆盖保护区。
- 滚动弹幕的轨道与保护区相交时禁用该轨道或调整垂直范围。
- 保护区不随弹幕密度缩小。
- 切换显示器或 DPI 后按归一化坐标恢复，再让用户确认。

## 7. 三重恢复机制

点击穿透窗口必须有三个互不依赖的恢复入口：

### 7.1 全局快捷键

- 默认紧急解锁：`Ctrl+Shift+F10`，允许用户修改。
- 默认暂停/继续：`Ctrl+Shift+F9`，允许用户修改。
- 默认清屏：`Ctrl+Shift+F8`，允许用户修改。

注册失败时必须显示冲突，不允许假装快捷键可用。快捷键触发后要有控制台状态反馈，但不在游戏画面上长期显示说明文字。

### 7.2 系统托盘

托盘菜单固定包含：

- `打开控制台`
- `暂停直播` / `继续直播`
- `隐藏弹幕` / `显示弹幕`
- `解锁弹幕层`
- `清屏`
- `停止直播`
- `退出 FakeLive`

`退出 FakeLive`必须先执行完整停止流程，而不是直接杀死渲染进程。

### 7.3 独立恢复窗

独立恢复窗由主进程管理，与弹幕层不是同一 BrowserWindow。它始终可点击，默认是小型图标工具条，可停靠屏幕边缘，包含暂停、清屏和解锁三个图标按钮；陌生图标提供悬停提示。

最终产品允许隐藏恢复窗，但前提是全局快捷键和托盘均已验证。黑客松演示建议保持恢复窗可见，作为点击穿透失败时的最后保障。

## 8. B 站式能力边界

“像 B 站”指核心观看与控制体验，不等于复制 B 站全部业务功能。

### 8.1 黑客松 P0

- 右向左滚动弹幕。
- 基本轨道防碰撞。
- 速度、全局密度和显示面积。
- 一套保证可读性的默认字体、颜色与描边。
- 暂停、继续、清屏、显示和隐藏。
- 过期弹幕丢弃。
- 不可关闭的最终内容安全过滤。

### 8.2 首个可用版本 P1

- 顶部和底部固定弹幕。
- 字号、颜色、描边、透明度的完整调整。
- 至少一个矩形保护区，随后扩展多个保护区和按应用预设。
- 关键词屏蔽、精确重复和近似重复抑制的用户配置。
- 测试弹幕和模拟爆点的完整校准工具。
- 按人格或风格隐藏。
- 顶部/底部/滚动类型独立开关。
- 减少动态效果模式。
- 最近弹幕辅助列表。
- 配置导入导出。
- 高密度性能面板和自适应降载。

### 8.3 最终产品 P2

- 人脸、字幕或游戏 HUD 的动态避让。
- 富文本、图片或自定义表情弹幕。
- 弹幕历史回放和视频导出。
- `+1`潮插件及手动/导演触发。
- 真实直播平台适配器。
- 人格包和过滤包分享。

黑客松明确不做真实 B 站/虎牙接入、插件市场、摄像头、完整系统声音理解或全部 B 站功能。

## 9. 多显示器、DPI 与窗口变化

### 9.1 最终产品模型

- 一个选中的捕获源可以对应一个或多个弹幕目标显示器。
- 每个目标显示器创建独立弹幕层和独立轨道调度器。
- 弹幕内容可镜像，也可按显示器分配；默认只发送到主弹幕目标。
- 使用 Electron 的`display.id`作为会话内标识，持久化时同时保存分辨率、缩放比和相对位置用于重新匹配。

### 9.2 黑客松约束

黑客松只需支持**一个明确选择的弹幕目标显示器**，但界面和数据结构不得把“主屏幕”写死。连接或移除显示器时：

- 目标仍存在：按新边界重建弹幕层。
- 目标消失：立即关闭弹幕层、暂停弹幕调度，控制台要求重新选择。
- 不自动跳到其他屏幕，避免意外遮挡或泄露。

### 9.3 DPI 规则

- 所有用户配置的保护区采用 0–1 归一化坐标保存。
- BrowserWindow 使用 DIP 布局，轨道测量以渲染器实际 CSS 像素为准。
- 监听显示器尺寸、旋转和缩放变化，变化后清除待显示轨道并重新布局。
- 需要覆盖 100%、125%、150%、200% 缩放和横竖屏组合。
- 长弹幕不得超出可见区域；最长单词或连续字符需要截断、缩放或拒绝，不允许撑开窗口。

## 10. 应用与异常状态

### 10.1 会话主状态

```text
启动检查 -> 待设置 -> 可开播 -> 启动中 -> 直播中
                                      |-> 已暂停
                                      |-> 停止中 -> 已结束 -> 可开播
```

`画面来源丢失`、`麦克风断开`、`AI 限流`和`部分人格失败`是附加降级标志，不应把主状态机扩展成大量互斥组合。

### 10.2 异常处理文案

| 场景 | 控制台文案 | 行为 |
| --- | --- | --- |
| 画面来源关闭 | `画面来源已断开，已停止发送截图。` | 取消依赖旧画面的请求，提供`重新选择来源` |
| 麦克风断开 | `麦克风已断开，当前仅根据画面回应。` | 停止音频轨道，保留视觉模式，提供`选择麦克风` |
| ASR 失败 | `语音识别暂不可用，AI 观众仍会看画面。` | 视觉模式继续，不复用旧转写 |
| API 认证失败 | `AI 密钥失效，已停止发送画面和转写。` | 停止新上传并要求重新连接 |
| HTTP 429 | `请求过快，AI 观众已自动减少到 8 位。` | 全局降并发和退避，不让 32 路分别重试 |
| 导演 AI 失败 | `人群导演暂不可用，当前保持基础热闹度。` | 使用用户基础热闹度，人物调用继续 |
| 单个人格失败 | `1 位 AI 观众暂时离开。` | 隔离该人格，不弹阻塞错误 |
| 弹幕目标移除 | `弹幕显示器已断开，弹幕已隐藏。` | 关闭窗口并暂停调度，要求重选 |
| 恢复快捷键冲突 | `紧急解锁快捷键不可用，请重新设置。` | 不允许只依赖失败快捷键开播 |
| 队列积压 | `部分弹幕已过期并丢弃。` | 丢弃旧项，不补播 |
| 全部 AI 不可用 | `AI 观众暂时离线，画面和转写已停止发送。` | 弹幕层仍可控制；默认不伪造上下文弹幕 |

错误通知应出现在控制台状态区和托盘；除密钥输入、数据删除等需要用户决定的场景外，不使用抢焦点模态框。

## 11. 无障碍与人体工学

- 所有控制台命令可键盘访问，有清晰焦点样式。
- 图标按钮使用熟悉图标；不熟悉的图标提供 tooltip 和无障碍名称。
- 状态不能只靠红绿颜色，必须同时有文字或图标。
- 提供`减少动态效果`：降低滚动速度变化、限制同时可见弹幕，并可将弹幕转换为淡入淡出的顶部/底部固定模式。
- 屏幕阅读器默认忽略持续移动的弹幕层，避免每条弹幕抢占朗读。
- P1 提供`最近弹幕`列表，允许屏幕阅读器和键盘用户按时间浏览，不与屏幕弹幕同步抢焦点。
- 支持 200% Windows 文本缩放；按钮文案允许换行但不得溢出。
- 控制台保持稳定尺寸约束，状态文字变化不能推挤开始、暂停和停止按钮。
- 闪烁、抖动、全屏白色高亮和快速缩放不用于爆点表现。

## 12. 内容设置的用户语言

内容设置不能只给一个含糊的“安全模式”。建议使用可预期的选项：

- `调侃强度`：温和 / 直接 / 嘴硬。
- `允许粗口`：关闭 / 少量 / 较多。
- `允许针对操作失误的嘲笑`：开关。
- `允许质疑开挂、运气或对手水平`：开关。
- `保护主播填写的称呼和个人词语`：词表。
- `屏蔽词`：本地列表，命中后不渲染。
- `相似弹幕`：严格合并 / 自然复读 / 爆点放宽。

以下底线不提供关闭开关：现实威胁、针对受保护群体的仇恨、鼓励自残、泄露个人隐私或凭据、涉及未成年人的色情内容。更完整策略见安全文档。

首次开播默认值固定为：`调侃强度=直接`、`允许粗口=关闭`、`直接嘲笑失误=关闭`、`允许梗式质疑=开启`。因此默认可以出现`?`、`开了？`和轻度操作吐槽，但不能出现`FW`或持续羞辱。

## 13. 可观测性与诊断界面

普通用户只看懂状态；高级诊断可以展示：

- 当前会话 ID 的短哈希。
- 画面采样频率和最近帧时间，不显示帧内容。
- 用户设置的决策频率/每秒请求上限，以及最近 10 秒实际决策率和请求率。
- ASR 最近成功时间，不显示完整转写。
- 活动人格、请求中人格、全局退避状态。
- P50/P95 响应延迟。
- 已显示、过期、去重、内容拦截和队列丢弃数量。
- 当前渲染 FPS 和同时可见弹幕数。

诊断导出默认脱敏：不含 API Key、请求头、图片 Base64、原始音频、完整转写和未过滤模型输出。

## 14. 黑客松演示脚本

1. 启动应用，展示已同意的云端说明和真实连接状态。
2. 选择 CSGO 画面来源、目标显示器、麦克风和`热闹游戏房`。
3. 通过真实麦克风电平与口令转写证明输入设备选择生效；扬声器测试属于 P1。
4. 运行弹幕校准，设置显示区域，并验证一次全局解锁。
5. 开始直播，证明弹幕层透明、置顶、点击穿透且不会自我采集。
6. 播放或实际触发单杀、三杀、杀人后死亡、零击杀死亡四个场景。
7. 展示三杀比单杀更密集，失误场景出现人格化调侃，主播说话被至少一位人格接住。
8. 触发模拟 429，展示全局降并发而非请求风暴。
9. 依次展示清屏、隐藏、暂停和恢复的不同语义。
10. 点击停止直播，证明画面、麦克风、SSE、队列和弹幕层全部结束。

## 15. UX 验收清单

### 黑客松必须证明

- 画面来源和弹幕目标是两个可独立选择的字段。
- 麦克风选择、真实电平和转写测试有效；P1 扬声器测试音从选定设备播放。
- 弹幕层对真实鼠标输入穿透，而不只是 Playwright 定位器点击成功。
- 全局快捷键、托盘和独立恢复窗至少各完成一次恢复操作。
- 100% 和 125% DPI 下无明显重叠、裁切或错位；最终产品扩展到 150% 和 200%。
- 暂停停止上传；隐藏不积压；清屏不停止 AI；停止释放全部资源。
- 同一事件的过期弹幕不会晚到。
- 控制台对限流、麦克风断开、来源丢失和导演失败给出明确状态。
- 直播画面不出现 FakeLive 自己的弹幕反馈循环。

### 待真实探针确认

- 从事件发生到第一条相关弹幕的可实现 P50/P95。
- `step-explore`真实最大稳定并发和限流行为。
- 目标机器在爆点密度下可维持的渲染 FPS。
- Electron 内容保护对目标采集路径的实际排除效果。
- 不同全屏游戏模式下置顶、焦点和点击穿透的兼容性。
