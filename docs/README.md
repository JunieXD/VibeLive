## 1. 这套文档是什么

这套文档把 FakeLive 定义为一个 **Windows 个人 AI 假直播陪伴工具**：软件持续理解用户正在玩的游戏、观看的视频和主播本人说的话，由一组具有稳定人格的 AI 观众生成短弹幕，并通过全屏透明、置顶、鼠标穿透的弹幕层从右向左飘过屏幕。

它解决的不是“怎样建立一个新的直播平台”，而是“当一个人想体验被观众围绕、被回应和被接梗的直播氛围时，怎样立即获得一个可控的 AI 观众席”。

这套文档同时描述两个时间尺度：

- **最终产品方向**：32 个会话内持久的 AI 人格、独立模型调用、独立人群导演、屏幕与主播语音理解、完整可配置弹幕舞台、稳定的桌面生命周期。
- **黑客松证明目标**：在几天内跑通一条真实、可录屏、可复验的闭环；没有实测通过的并发、协议和平台能力不提前宣称完成。

## 4. 一句话产品定义

**FakeLive 是一个把当前屏幕和主播说话实时转化为个性化 AI 弹幕的 Windows 个人观众模拟器。**

### 对外推荐表述

- AI 观众模拟器
- 个人假直播陪伴工具
- 单机可控的 AI 直播间氛围层

### 不应使用的表述

- “治疗孤独症”或任何医疗、心理治疗承诺
- “替代真实朋友、家人或专业帮助”
- 把 AI 观众冒充成真实在线用户
- “完整复刻 B 站/虎牙”
- 未经实测的“32 路稳定并发”“零数据留存”“任何游戏都能识别”

## 5. 已确定的产品不变量

1. **AI 身份透明**：界面明确标注“AI 观众”和“模拟在线”，不伪造真人。
2. **桌面级弹幕**：输出不是聊天侧栏，而是覆盖目标显示器的透明弹幕层。
3. **点击穿透**：直播态弹幕层不抢鼠标与键盘；必须有全局快捷键、托盘和独立解锁窗三条恢复路径。
4. **多模态上下文**：画面是核心输入，主播麦克风转写是完整体验的核心输入。
5. **云端模型**：第一版使用内部 `step-explore`，通过 Anthropic Messages 风格的 `/v1/messages` 调用。
6. **32 个逻辑人格**：每个人格有独立身份、提示、会话历史、沉默判断和独立调用语义；不使用“一次调用伪装 32 人”的批量生成作为最终形态。
7. **导演不写台词**：人群导演只判断事件强度、目标活跃人数和爆发时长，具体弹幕由人格生成。
8. **允许安静**：人格可以返回零条弹幕；用户也可切换为“持续热闹”的冷场策略。
9. **短而及时**：单人格每次返回 0 至 2 条短弹幕，过期响应必须丢弃。
10. **真实证据优先**：图片格式、SSE 事件、限流、并发上限、云端留存和音频能力在真实探针前都属于未知。

## 7. 关键术语

| 术语 | 定义 |
| --- | --- |
| AI 观众 | 一个具有稳定人格、独立上下文和独立发言决定的逻辑角色 |
| 人格包 | 一组适合特定氛围的 AI 观众配置，例如“默认大杂烩”“友好陪练” |
| 观察窗口 | 最近 10 或 20 秒的画面采样与主播转写；不等于每次请求必须发送全部帧 |
| 观察快照 | 从观察窗口选择出的有时效性的模型输入，带时间戳和过期时间 |
| 人群导演 | 完整 P0 中是只控制热闹程度和调度、不写弹幕文案的独立 AI 会话；规则 Detector 只允许作为明确显示的降级路径 |
| 冷场策略 | “自然冷场”允许无人发言；“持续热闹”允许基于背景和长期主题接梗 |
| 爆点 | 可能值得短时间提高活跃人格数的事件，例如三杀或极限反杀 |
| 弹幕命令 | 已通过结构与内容校验、带显示模式、速度、优先级和 TTL 的渲染指令 |
| 模拟在线 | 正在参与本次会话的 AI 人格数量，不代表真人观众人数 |

## 8. 当前执行基线

- 黑客松演示以“32 个可配置身份 + 真实并发阶梯实测”为标准；32 路同时成功不是硬门槛，声明统一使用实测上限 N。
- 捕获环按约 1 fps 保存最近 10/20 秒；每次请求默认发送 2 至 4 个关键帧、时间戳和转写摘要，不无条件复制全部帧。
- 语音通过 StepFun `stepaudio-2.5-asr-stream` 的双向 WebSocket 转写，再把最终文本与画面一起送入 `step-explore`；两条链路共用开发者自有 StepFun Key，但健康状态与数据类型分开显示。
- StepAudio 默认使用服务端 VAD，本地只做采集、重采样和有界分块，以减少游戏同时运行时的 CPU、内存和 GPU 占用。
- 首次开播默认“直接调侃但不爆粗”：粗口、`FW` 和直接羞辱关闭，用户主动开启后才允许更强攻击性人格。
- 完整模式需要麦克风；麦克风不可用时允许用户明确选择“仅画面模式”，但该会话不能算“语音陪伴验收通过”。
- 黑客松只承诺一个弹幕目标显示器，以及窗口化或无边框游戏；独占全屏与多显示器属于专项验证或后续。
- 扬声器选择用于输出测试、提示音和未来 TTS，不等同于采集系统声音。
- 人格记忆默认仅在一次直播会话中持久，停播后不保存原始截图、录音或完整转写。
- `+1` 波可先作为受控实验功能验证，不为它提前建设通用插件沙箱。

## 9. 文档维护规则

1. 改变产品边界时，先更新决策日志，再同步专题文档。
2. 对未验证外部能力使用“待探针”“候选”“目标”，不得写成事实。
3. 每项“完成”必须链接到 [09_TEST_AND_ACCEPTANCE.md](./09_TEST_AND_ACCEPTANCE.md) 定义的证据。
4. 最终产品能力和黑客松范围必须分开写，不能用未来架构掩盖当前未完成。
5. 任何新增上传内容都必须同步更新隐私告知、最小化策略和停止清理验收。
6. 任何新增人格都必须声明触发、禁区、攻击性等级、静默倾向和最短可判定示例。
