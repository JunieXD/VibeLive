# AI 观众发言产品规格

> 状态：已确认的产品规格
>
> 更新日期：2026-07-24
>
> 适用范围：AI 观众的发言时机、上下文、独立判断、画面记录、历史记录与展示行为

## 1. 目的与优先级

本文规定 AI 观众在一次直播中的发言机制，是面向产品、交互和验收的行为规格，不限定具体模型供应商或代码结构。

本文覆盖此前文档中与以下事项冲突的旧规则：由 Director 决定话题或发言者、只让少量候选观众调用模型、生成后按数量丢弃回复、画面变化直接触发发言、以及观众弹幕自动引发无限接话。

## 2. 核心原则

1. 不设 Director。系统不得通过中心模型决定谁说话、说什么、当前话题或房间情绪。
2. 每位在场观众都是独立个体。面对用户输入时，每位观众各进行一次独立的模型思考。
3. 一次模型思考同时决定“是否发言”和“发言内容”，不能先由中心系统筛掉部分观众。
4. 观众发言由个人性格、当前画面、用户话语、公开历史和个人状态共同决定，而不是由事后展示数量限制决定。
5. 只要观众决定发言，其生成内容就必须展示。系统不得出现“已经生成但不展示”的回复。
6. 用户的文字、完整语音文本、截图和已公开的观众发言都属于直播记录，不应因短时间窗口而自动丢失。

## 3. 基本名词

### 3.1 用户发言

用户主动发送的一条文字，或用户连续说完的一段语音。一次用户发言可以包含多句完整句子。

### 3.2 一轮观众思考

由一条用户发言触发的一次独立反应机会。每位在场、未被禁言的观众各调用一次模型，并独立选择沉默或发言。

### 3.3 公开发言

已经显示给用户的观众消息。只有公开发言会进入其他观众后续可见的对话历史。

### 3.4 画面时间线

按固定节奏积累的屏幕截图序列。它记录最近一段画面，不负责判断是否该发言。

## 4. 固定参数

| 参数 | 默认值 | 行为含义 |
| --- | ---: | --- |
| 句子结束的静音时间 | 0.8 秒 | 用于将语音识别结果保存为完整句子。 |
| 用户发言结束的静音时间 | 1.5 秒 | 用户连续说多句时，停顿达到该时间才开启一轮观众思考。 |
| 连续讲话最长时长 | 不强制截断 | 不按固定秒数切开用户讲话。 |
| 截图频率 | 每秒 1 张 | 正常持续采样。 |
| 画面时间线范围 | 最近 120 秒 | 最多保留 120 张原始截图作为本轮视觉来源。 |
| 相邻截图合并标准 | 相似度达到 90% | 仅用于去除发送给模型的重复图片。 |
| 静态画面保底间隔 | 每 5 秒 1 张 | 即使画面基本不变，也保留时间连续性。 |
| 每轮发送的精简截图上限 | 60 张 | 从 120 张原图中按时间和信息量选择。 |
| 对话历史上下文上限 | 24,000 个中文字符 | 不超过时直接发送全部历史。 |
| 历史摘要上限 | 6,000 个中文字符 | 超长后保存较早内容的共享摘要。 |
| 近期原文上限 | 18,000 个中文字符 | 与历史摘要共同构成模型可读历史。 |
| 每位观众每轮模型调用数 | 1 次 | 在一次调用内返回是否发言和发言内容。 |
| 观众发言推荐长度 | 20 个中文字符以内 | 提示词中的优先表达长度。 |
| 观众发言绝对长度 | 160 个中文字符 | 超出后在实际展示前硬截断。 |
| 个人冷却时间 | 15 秒 | 刚公开发言的观众在此期间应明显更克制。 |
| 热闹模式 | 默认关闭 | 开启后才允许用户沉默时的主动发言。 |
| 热闹模式等待时间 | 30 秒 | 用户无输入达到该时间后，开启一次主动发言机会。 |
| 热闹模式参与观众数 | 2 位 | 轮换安排两位观众独立思考，生成内容全部展示。 |

## 5. 输入记录与触发规则

### 5.1 用户文字

用户发送文字后，该原文立即写入完整对话记录，并立刻开启一轮观众思考。相邻的文字消息仍是不同输入，不因时间接近而合并或覆盖。

### 5.2 用户语音

应用持续采集用户麦克风，但不得按固定两秒之类的时长把内容当作用户发言边界。

- 连续静音约 0.8 秒后，语音识别结果可以保存为一句完整句子。
- 用户在句子间继续讲话时，所有句子都按时间顺序追加到同一段用户发言中。
- 自最后一句后连续静音达到 1.5 秒，才把这段完整发言写入触发上下文，开启一轮观众思考。
- 用户一直讲话时，系统持续记录，不因长度到达某个数值而强制结束或删除内容。
- 语音识别只进行一次，最终文本进入共享记录后提供给所有观众；观众不各自进行语音识别。

### 5.3 画面采样

画面每秒采样一次并写入时间线。采样本身不触发观众思考，画面变化大小也不触发观众思考。

用户说话时，系统不需要额外卡在语音开始或结束时截图。截图和语音都带时间，模型使用正常积累、与该次用户发言相邻的画面时间线。

### 5.4 观众发言

观众公开发言不会自动触发另一轮观众思考。这样可以避免观众之间无限递归接话。

用户在新一轮输入到来后，上一轮已经开始的观众思考仍可完成并正常展示。每条回复必须关联它实际回应的用户发言，避免用户误以为它在回答后来的内容。

### 5.5 热闹模式

默认状态下，用户沉默时观众不主动聊天。

开启热闹模式后，用户连续 30 秒没有新文字或语音输入，系统按轮换和距离上次公开发言的时间，安排 2 位观众进入一次主动思考。两位观众各自决定沉默或发言；所有决定发言的内容都展示。下一次主动机会重新等待 30 秒。

## 6. 画面时间线与精简规则

### 6.1 原始记录

每轮视觉上下文以最近 120 秒的正常截图为来源。完整原始截图不能因为相似而被删除；相似度判断只影响本次发给模型的精简画面包。

直播开始不足 120 秒时，使用已积累的全部截图。正常情况下，画面采样在观众思考前已经启动，因此每轮都应拥有一段连续画面，而不是仅有一张“最近截图”。

### 6.2 精简步骤

系统按时间顺序处理 120 张原始截图：

1. 将相邻且相似度达到 90% 的截图归为同一段连续画面。
2. 每段选择最清晰、信息最多的一张代表图。
3. 对新出现的文字、人物、物体、界面切换、明显操作和游戏关键局面提高保留优先级。
4. 即使画面持续相似，也至少每 5 秒保留一张代表图。
5. 若候选超过 60 张，优先保留与本次用户发言时间更接近、信息变化更多、且能维持完整时间顺序的图片。
6. 最终图片按时间排序，并保留各自的时间信息。

这套规则的目标是让 CSGO 等快速画面保留更多关键操作，让静态桌面减少重复图；它不是“显著变化才值得发言”的规则。

## 7. 对话历史与记忆

### 7.1 永久原始记录

整场直播的用户文字、最终语音文本和已公开观众发言都保存为原始记录，不以 120 秒或固定事件条数为由自动删除。

每条公开消息至少保存发言者、时间、内容、回复对象和所回复的用户发言。这些关系在后续上下文中不得丢失。

### 7.2 模型可读历史

历史文本不超过 24,000 个中文字符时，直接完整发送给每位观众。

超过上限后，系统执行一次共享压缩：将较早的一半历史连同已有摘要交给一个模型生成新的历史摘要，摘要最长 6,000 个中文字符；较新的一半保留原文。此后每位观众读取“共享历史摘要 + 最近原文 + 本次用户发言”，其中近期原文最多保留 18,000 个中文字符。

后续再次超长时，重复同一机制：更新共享摘要，保留最新一半原文。原始完整记录始终不变，摘要只用于缩短每轮模型材料。

摘要由系统统一生成一次，所有观众共用。它不负责决定谁说话，也不代表 Director。

## 8. 每位观众的独立思考

### 8.1 每轮材料

每位观众收到相同的公共材料：

- 本次完整用户发言；
- 可读的对话历史；
- 最近两分钟的精简画面时间线；
- 所有此前已经公开的观众发言及其关系；
- 本次用户是否点名某位观众。

此外，每位观众还收到只有自己拥有的材料：人格、表达方式、兴趣、个人状态、最近公开发言、冷却状态和个人短期记忆。

同一轮中，观众看不到其他观众刚生成但尚未公开的回复。只有已经展示的发言才会进入下一轮所有人可见的历史。

### 8.2 判断含义

观众不使用抽象的“是否有价值”标准，而是从一个真实观众的视角判断此刻是否自然想开口。

以 CSGO 为例，观众会结合当前是对枪、残局、死亡回放、买枪阶段、普通移动还是菜单；也会结合主播是否在提问、庆祝、吐槽或沉默，以及自己是战术型、起哄型、安静型还是毒舌型观众。

- 主播 1v3 残局时，安静型观众通常克制；起哄型观众可能短促助威。
- 主播在买枪阶段询问配装时，战术型观众更可能给出建议。
- 主播只是正常移动、没有特别事件时，大部分观众会选择沉默。
- 观众刚给过相同建议时，应因个人冷却和重复感而保持克制。

被主播点名是强烈的个人互动信号，但被点名者仍保留自主决定沉默或发言的权利。

### 8.3 单次模型输出

每位观众每轮只调用一次模型。模型必须按结构返回：

```json
{
  "是否发言": true,
  "发言类型": "提醒",
  "回复对象": "主播",
  "内容": "这把可以先封烟。"
}
```

当“是否发言”为 `false` 时，“发言类型”“回复对象”和“内容”必须为空。当其为 `true` 时，内容必须非空、与上下文相关并符合该观众人格。

提示词必须要求优先使用 20 个中文字符以内的短句。若模型仍返回超过 160 个中文字符的内容，系统在实际发送和展示前直接截断到前 160 个字符；不会因为过长而丢弃整条消息。

### 8.4 冷却

个人冷却时间为 15 秒。观众刚公开发言后的 15 秒内，提示词和个人状态都应让其明显更克制，但这不是中心系统的硬性禁言。被点名、关键局面或符合人格的强烈反应仍可让观众自己决定发言。

## 9. 展示与公开顺序

用户输入触发的一轮中，不设置展示数量上限。每位在场、可发言观众各调用一次模型；凡返回“是否发言”为 `true` 的消息均应公开展示。

系统不得先生成所有内容，再按所谓“房间密度”或“内容排名”隐藏部分结果。实际发言密度应来自每位观众独立的沉默判断、人格和个人冷却，而非事后删选。

公开后的消息立即进入共享对话历史，并保存与用户发言的关联。尚未公开的并行结果不影响同一轮其他观众；公开顺序不改变这些观众已经做出的决定。

## 10. 验收场景

### 10.1 完整语音

用户连续说三句，中间只有短暂停顿，最终停顿达到 1.5 秒。系统保留三句完整文本，并只启动一轮观众思考；不出现两秒音频碎片或漏字。

### 10.2 CSGO 对局

用户在买枪阶段问“这把怎么配”。系统给每位观众提供近期两分钟、最多 60 张的精简画面时间线和完整提问。战术型观众可简短建议，起哄型或安静型观众可选择沉默；不存在中心角色指定谁回答。

### 10.3 历史超长

历史达到 24,000 个中文字符以上时，系统只进行一次共享摘要调用。之后所有观众收到相同摘要和较新的原文，整场原始记录仍可完整保存。

### 10.4 多人同时发言

同一轮有 6 位观众返回“是否发言”为 `true`。6 条都必须展示；系统不得因数量多而删除其中任何一条。

### 10.5 热闹模式

开启热闹模式后，用户沉默 30 秒。系统仅安排 2 位轮换观众思考；其中 1 位选择发言，则展示这 1 条。观众发言本身不会再触发其他观众接话。

## 11. 非目标

- 不要求观众弹幕自动互相无限接话。
- 不允许 Director、全局主题模型或展示配额决定用户输入轮中谁可以说话。
- 不因画面变化大小自动触发观众发言。
- 不按固定短时间片切碎用户语音。
- 不因展示数量限制丢弃已经生成的观众内容。
