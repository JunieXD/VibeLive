# FakeLive 数天 Hackathon 交付计划

> 目标：从零做出一条真实、可运行、可证明的 Windows AI 假直播链路，而不是只展示 UI 或脚本动画。  
> 产品核心：选择屏幕和麦克风后，多个稳定 AI 观众人格理解近期画面与主播转写，并通过透明、置顶、点击穿透的横向弹幕层回应。  
> 计划原则：先证明最不确定的真实 API，再用假实现锁定内部合同，最后逐层替换为真实能力。

## 1. 最终演示要证明什么

Hackathon 结束时，评委应能亲自看到以下闭环：

```text
选择一个窗口/显示器 + 选择并测试麦克风
  -> 明确同意把近期截图和主播转写发送到 StepFun
  -> 开始假直播
  -> 本地持续采样近期画面并转写主播说话
  -> 多个独立人格通过真实 step-explore 请求作出短反应
  -> 反应经过安全、去重、TTL 与密度控制
  -> 弹幕从屏幕右侧向左移动且不挡住下层点击
  -> 三杀等爆点比普通击杀产生更密集但有上限的群体反应
  -> 暂停/清屏/停止/紧急解锁立即生效
```

成功不是“看起来像直播间”，而是每一段关键链路都有证据：真实图片请求、真实转写、真实多个独立人格、真实 SSE、真实原生点击穿透、真实停止清理、真实并发阶梯和真实延迟记录。

## 2. 第一版 P0 范围

### 2.1 必须完成

#### 桌面与采集

- Windows 11 作为演示基线。
- 一个控制窗口。
- 选择一个捕获来源：单个窗口或单个显示器。
- 选择一个弹幕目标显示器；Hackathon 只要求单屏目标。
- 一个透明、无边框、置顶、任务栏隐藏的弹幕窗口。
- 开播后弹幕窗口默认点击穿透，并有独立快捷键、托盘和恢复窗作为解锁路径。
- 排除 FakeLive 控制窗、弹幕窗和恢复窗的自捕获，并进行真实录制验证。

#### 弹幕

- 从右到左滚动。
- 基本轨道防撞，避免同轨后发弹幕追上前一条。
- 速度、密度和显示区域可调，先提供一套可读默认字体/描边。
- 支持暂停、恢复、隐藏、清屏和停止。
- 支持不可关闭的最终安全过滤和基础精确重复抑制。
- 每条候选弹幕有 TTL；过期回应绝不补发。

顶部/底部固定弹幕、矩形 HUD 保护区、完整样式面板、关键词与近似重复配置属于 P1。领域命令可以预留类型，但 P0 不为未实现能力展示开关。

#### 语音真实链路

- 枚举 Windows 麦克风，选择设备并显示真实输入电平。
- 使用 AudioWorklet 分块与 StepAudio `stepaudio-2.5-asr-stream` WebSocket 把主播语音转换为带时间戳文本；默认使用 `server_vad`，并具备明确告知、停止、心跳和限流处理。
- 至少一个演示步骤证明人格引用了主播刚刚说过的话，而不是只看图。
- 麦克风断开时进入“仅画面回应”的降级状态并提示重选，不能静默假装语音仍然有效。
- 扬声器选择与系统音频理解均不属于 P0；若已有现成能力，只作为额外展示。

#### AI

- 真实调用 `POST https://api.stepfun.com/v1/messages`。
- 使用 `x-api-key`、`anthropic-version: 2023-06-01` 和 Anthropic Messages 内容格式。
- 不使用 OpenAI `/v1/chat/completions`，不发送 `thinking`。
- 真实图片输入、SSE 流式读取、取消、超时和错误体均经过探针验证。
- 预置 32 个稳定人格配置，每个人格有独立身份与短期上下文。
- 演示闭环至少有 4 个真实独立人格同时走通；并发上限以 1→4→8→16→32 实测结果为准。
- 每个人格最多一个在途请求，另保留一个“最新观察”；新观察覆盖旧待处理观察，避免积压。
- 高级设置允许选择决策频率和每秒请求硬上限；控制台同时显示目标值与实际 requests/s，限流器可以自动下调。
- 独立人群导演只返回事件、强度、目标活跃人数和 TTL，不直接写最终弹幕。
- 所有 429 由全局 Rate Controller 协调退避，不能 32 路各自重试。

#### CSGO 事件证明

- 单次击杀。
- 三杀或明确多杀。
- 击杀后自己死亡。
- 一个敌人没杀就死亡。

四类事件用固定、无敏感信息的回放素材做可重复验收；演示当天可追加实时游戏，但不能只靠一次不可复现的现场操作。

#### 隐私与生命周期

- 未同意前不发送截图、转写、背景或弹幕上下文。
- 直播中明确显示采集、麦克风和云端请求状态。
- 暂停停止采集、转写和请求，并清空待处理上下文。
- 停止中止 SSE、停止媒体轨道、清空帧/转写/候选弹幕/轨道队列。
- API Key 使用 `safeStorage`；除一次性隔离 KeyEntry 中的用户当前输入外，Control/Capture/Overlay/Unlock Renderer 均不可访问。
- 日志与证据包不含 Key、图片 Base64、原始音频和完整转写。

### 2.2 P0 明确不做

- 多显示器同时铺设多个弹幕层。
- 跟随游戏窗口移动/缩放的原生窗口绑定。
- 真实 B 站、虎牙弹幕接入和直播账号登录。
- 第三方插件市场或公开插件 SDK。
- `+1` 自动波次插件；只在核心接口中预留 `waveId`/事件钩子。
- 手环专用 Bluetooth GATT、串口或厂商 SDK；若手环表现为标准 Windows 麦克风，则自然可用。
- 系统音频理解、摄像头、表情识别。
- 跨会话人格长期记忆、云端账号、同步和社交功能。
- 完整 B 站高级弹幕、蒙版、对象识别避让、历史回放和视频导出。
- “任意游戏的高精度事件识别”。第一版只证明 CSGO 四类事件和通用画面回应。

## 3. 关于“32 个 AI”的诚实定义

第一版存在三个不同数字，文案和演示不能混为一谈：

| 概念 | 第一版含义 | 可以怎样声明 |
| --- | --- | --- |
| 人格库大小 | 预置约 32 个可编辑、会话内稳定的观众身份 | “内置 32 个观众人格” |
| 当前活跃人格数 | 调度器在某个观察周期选中的身份数量 | “当前有 N 位 AI 观众正在思考” |
| 实测并发能力 | 在当前 StepFun 白名单、网络和机器上真实成功的同时在途请求数 | 只能引用当次 1/4/8/16/32 阶梯结果 |

以下证据都不能证明“真实 32 并发”：

- 配置文件里有 32 条人格。
- 创建了 32 个 Promise。
- 用 Fake Server 返回了 32 条响应。
- 在同一个模型回复里模拟了 32 个名字。
- 32 个任务最终都完成，但从未同时在途。

Hackathon 的最低真实承诺是：**32 个稳定身份可配置，至少 4 个身份走通真实端到端链路，并保存并发阶梯测得的最大成功档位 N。** 如果 32 档未通过，就展示实际 N、429/超时证据和全局降级行为，不把失败隐藏掉。

## 4. 交付门禁总览

| Gate | 目标 | 退出条件 | 失败时动作 |
| --- | --- | --- | --- |
| Gate 0 | 真实 `step-explore` 能力探针 | 文本、图片、SSE、取消、错误体均有脱敏证据 | 不进入 32 人格开发；先修正协议或联系白名单对接人 |
| Gate 1 | 假数据端到端桌面骨架 | 假观察能经过合同校验出现在真实透明弹幕层 | 固定窗口/IPC/轨道生命周期，不接真实模型 |
| Gate 2 | 真实画面 + 真实语音 + 1 人格 | 一条截图/转写触发的真实回应可展示且可取消 | 分别降级检查采集、ASR、StepFun，不并行扩大范围 |
| Gate 3 | 多人格、导演与限流 | 至少 4 个独立人格、事件爆发、全局 429 控制可证明 | 保持基础并发，导演失败回退，不牺牲停止链路 |
| Gate 4 | P0 验收与稳定演示 | P0 全绿、30 分钟稳定、证据包完整 | 冻结功能，按严重度修复；不新增视觉花活 |

每个 Gate 都必须先生成证据再宣告通过。计划日期不能替代退出条件。

## 5. Gate 0：真实 API 探针优先

### 5.1 为什么先做

`step-explore` 是内部模型，当前已知手册只确认端点和 Anthropic Messages 协议。图片 Content Block、图片数量/字节限制、SSE 事件、实际并发、RPM、429 Body 和响应时延仍需要真实凭据验证。这些不确定性会直接改变截图窗口、调度器和错误处理设计。

### 5.2 探针顺序

1. **认证与纯文本**：最小 `messages` 请求，确认状态码、响应 JSON、usage 字段和错误体。
2. **单张图片**：使用专门制作的无隐私测试图，验证图片 Block 结构、MIME 和尺寸。
3. **多张图片**：逐步尝试 2、5、10、20 张，记录请求字节、服务端接受上限和总延迟。
4. **SSE**：确认至少收到多个增量事件，而不是只在结束时拿到整段文本。
5. **取消**：流式读取中途 Abort，确认客户端停止读取且任务资源释放。
6. **错误路径**：无效模型、缺少字段、错误图片、超时和 429 Fixture，记录可安全解析的错误格式。
7. **上下文策略**：用 10 秒与 20 秒代表帧窗口比较响应相关性、首 Token 和完整响应延迟。

### 5.3 探针产物

```text
artifacts/api-probe/<run-id>/
  run-manifest.json
  text-response.redacted.json
  image-response.redacted.json
  sse-events.redacted.jsonl
  cancellation.json
  errors.redacted.jsonl
  limits.md
  latency.json
```

脱敏后的请求只保留模型、消息块类型、图片数量/字节数、文本字符数和时间信息。不得保存 Key、图片 Base64、真实私人截图或完整用户转写。

### 5.4 Gate 0 通过条件

- 文本请求真实返回 2xx。
- 至少一张真实图片被模型理解，回答能引用图中受控事实。
- SSE framing 至少产生一个可观察内容增量，并出现探针确认的明确终态；短弹幕只有一个内容 delta 也可以通过。
- 取消能在规定时间内停止客户端读取，且无后续回调进入旧会话。
- 错误体可以映射到明确的应用状态，不导致进程崩溃。
- 探针结果明确标注图片上限、已验证 MIME、实际首 Token/完整延迟和所有未知项。

## 6. 并发阶梯：1 → 4 → 8 → 16 → 32

### 6.1 执行规则

- 必须在 Gate 0 基本协议通过后执行。
- 使用相同的无隐私图像集、固定短提示、固定 `max_tokens` 和相近网络条件。
- 每档至少 3 轮，轮次之间冷却；不得为了“测 429”恶意持续压测生产服务。
- 每个身份携带独立 `personaId` 与独立会话历史，不能把一条响应复制 32 次。
- 记录实际同时在途数，而不仅是任务总数。
- 429 遵守 `Retry-After`（若存在）和全局抖动退避。
- 某一档连续失败达到退出规则后停止向上，不用无限重试硬凑通过。

### 6.2 每档记录

- 成功数、失败数、取消数、429 数、5xx 数。
- 首 Token P50/P95、完整响应 P50/P95。
- 峰值在途请求、平均在途请求。
- 全局待处理队列峰值和丢弃的过期观察数。
- 进程 CPU、内存和网络发送字节。
- 回应与人格身份匹配率、Schema 有效率。

### 6.3 通过与停止规则

- 一档 3 轮均无无限重试、无进程崩溃、无身份串线，才进入下一档。
- 429 本身不是产品失败；出现 429 后能全局降压并恢复才是正确行为。
- 若某档成功率低于 90%、P95 超过事件 TTL 或服务方明确限制更低，则把上一档记为当前“已验证上限”。
- 32 档未通过时，UI 默认最大值不能硬设为 32；可展示 32 身份库，但活跃并发上限采用实测值或服务端配置。

## 7. 四天参考排期

排期按四个完整开发日设计。只有三天时继续压缩可选视觉设置，不压缩 Gate 0、语音真实链路、停止清理和 P0 验收。

### Day 0 / 启动半天：事实确认与冻结合同

**工作**

- 完成 Gate 0 API 探针。
- 确认 StepFun 白名单、Key 注入方式、并发测试窗口。
- 固定 `ObservationSnapshot`、`PersonaDecision`、`CrowdDecision`、`BarrageCommand`、生命周期事件等运行时 Schema。
- 建立 L2 去敏回放语料：四类 CSGO 事件各 3 段、无事件/菜单至少 3 段、主播口令与提问至少 5 段；另准备黑屏、切源和来源结束等异常素材。
- 为每段素材记录授权/来源、事件时间、允许反应、禁止断言、最后有效显示时间和文件哈希。
- 建立 `artifacts/` 证据目录规范与脱敏检查。

**退出物**

- 脱敏的真实图片/SSE/取消证据。
- 已签字的 P0 与非目标清单。
- 可用的协议 Fake Server Fixture。
- 可重复回放的媒体清单和标注文件；缺失样本必须进入当日阻断列表，不能在演示前临时用一次现场操作替代。
- 所有仍未知的外部事实列表。

### Day 1：桌面骨架、捕获和弹幕层

**上午**

- 建立 Electron Main、Control Renderer、Capture Renderer、Overlay Renderer、Unlock Renderer 的进程边界。
- 完成会话状态机和强类型 IPC。
- 选择捕获源、弹幕目标屏幕和媒体权限。
- 完成无边框透明置顶窗口、托盘与恢复快捷键。

**下午**

- 接入弹幕引擎适配层或最小轨道调度器。
- 完成 RTL、轨道防撞、速度、密度、显示区域、TTL、暂停和清屏。
- 用 Fake Persona Engine 发送确定性弹幕。
- 真实验证点击穿透、自捕获排除和紧急解锁。

**当日 Gate**

- 假观察经完整 IPC/Schema/队列出现在真实透明弹幕层。
- 下层测试按钮能通过弹幕窗中心点被真实点击。
- 捕获样本中看不到稳定的自反馈弹幕循环。

### Day 2：真实语音与单人格闭环

**上午**

- 麦克风枚举、选择、实时电平和断连事件。
- AudioWorklet 与 StepAudio WebSocket `SpeechProvider`；完成 PCM/WAV wire、server VAD、累计 delta、最终 transcript、取消、心跳和超时 Spike，本地 Runtime 仅作非阻塞备选。
- 可选：若核心链路提前完成，再做扬声器枚举与测试音。
- 构建近期帧环形缓冲和带时间戳转写窗口。

**下午**

- 实现 StepExploreClient：SSE、超时、取消、错误映射和日志脱敏。
- 接入一个真实人格，验证图片 + 转写联合上下文。
- 完成响应 Schema 校验、安全过滤、去重和 TTL。
- 完成暂停/停止的代次失效与资源清理。

**当日 Gate**

- 人格能说出受控画面事实，并引用刚刚说出的测试语句。
- 取消后旧响应不会出现在屏幕上。
- 麦克风断开会明确降级，不会卡死会话。

### Day 3：多人格、人群导演与故障降级

**上午**

- 导入 32 个人格配置，保证会话内身份稳定、历史隔离。
- Persona Scheduler：每人格最多一个在途、只保留最新待处理观察、过期丢弃。
- 从 1 扩到 4 个真实人格；再按阶梯验证 8/16/32。
- 完成全局 Rate Controller、429 退避、熔断与半开恢复。

**下午**

- 人群导演输出事件强度、目标人数、爆发时间和事件键。
- CSGO 四事件回放与爆发去重。
- 冷场策略：“自然冷场”与“持续热闹”。
- 攻击性人格分级、硬安全过滤、基础精确去重和全局密度上限。

**当日 Gate**

- 至少 4 个真实人格不串身份、不串历史。
- 三杀五秒窗口的有效弹幕数明显高于单杀，同时不突破密度上限。
- 导演失败回到基础活跃度；429 不产生重试风暴。

### Day 4：验收、稳定性、演示封版

**上午**

- 执行 [09_TEST_AND_ACCEPTANCE.md](./09_TEST_AND_ACCEPTANCE.md) 的 P0 全量矩阵。
- 30 分钟长稳测试，收集延迟、CPU、内存、队列和资源清理证据。
- 修复 P0/P1 缺陷，不新增功能。
- 完成安全/隐私证据和诊断包秘密扫描。

**下午**

- 按正式演示脚本彩排两遍：正常链路、断网/429 降级各一遍。
- 固定可复现素材、模型配置、默认人格包和弹幕样式。
- 输出一页实测指标，诚实列出并发上限和未知项。
- 打包 Windows 演示构建并在干净用户配置下重跑启动流程。

**封版条件**

- P0 无阻断缺陷。
- 30 分钟无崩溃、无无界队列、停止后资源为零。
- 演示机器至少两次完整彩排成功。
- 离线/限流时有明确降级，不出现无限加载。

## 8. 工作流与责任分工

团队人数未知时采用“责任帽”而非固定人名。一个人可以承担多个帽子，但每个工作项只能有一个最终 Owner。

| 责任帽 | 主要所有权 | 必须交付 |
| --- | --- | --- |
| Product / Demo Owner | P0 冻结、用户文案、人格包、CSGO 素材、演示脚本 | 范围清单、演示输入、变更裁决、诚实声明 |
| Desktop Owner | Electron Main、窗口、权限、快捷键、托盘、IPC、打包 | 点击穿透、捕获排除、恢复路径、停止生命周期 |
| Capture / Audio Owner | 捕获源、帧缓冲、AudioWorklet/VAD、ASR、设备选择 | 真实帧/转写、设备断连、资源释放证据 |
| AI Runtime Owner | StepExploreClient、人格引擎、导演、调度、429、Schema | 探针、独立人格、并发阶梯、延迟和故障证据 |
| Barrage / UX Owner | 轨道、密度、显示区域、设置、状态与错误文案 | RTL 可读性、控制即时性、校准与降级界面 |
| Verification Owner | L0-L5 测试、证据采集、长稳、阻断缺陷裁决 | 可复现实验、证据包、最终验收报告 |
| Privacy / Safety Reviewer | 同意、Key、日志、输出安全、脱敏 | 红线用例、网络前置同意、秘密扫描、发布审查 |

### 8.1 共享文件冲突规则

- 每个模块预先指定 Owner，其他人通过接口合同集成，不并行大改共享入口。
- 运行时合同文件由 AI Runtime Owner 起草，Desktop/Audio/Barrage 共同审查后冻结。
- P0 冻结后，所有新增需求先进入“后续项”，只有修复阻断缺陷才能改变主链路。
- 验证 Owner 不以作者的单元测试作为唯一证据，关键路径需要独立复跑。

## 9. 依赖图与先决条件

```text
StepFun 白名单 + API Key
  -> Gate 0 协议 Fixture
      -> StepExploreClient
          -> 1 人格真实闭环
              -> 多人格调度
                  -> 人群导演与并发阶梯

Electron 窗口与 IPC
  -> 捕获源 + Overlay
      -> 自捕获排除 + 点击穿透
          -> BarrageCommand 真正展示

麦克风权限 + StepAudio SpeechProvider
  -> 设备选择 + AudioWorklet + server VAD
      -> 时间戳转写
          -> ObservationSnapshot

固定 CSGO 素材 + 可控语音脚本
  -> L2 回放
      -> CSGO 四事件验收 + 延迟统计
```

### 9.1 开发开始前必须备齐

- 已开通 `step-explore` 的 UID/Key，且 Key 不进入仓库。
- 开发者自有 StepFun Key 同时具备 Step-explore 与 StepAudio 权限；配置一次，两个健康检查分别通过。
- 原型不建设共享额度网关；任何产品内嵌公共 Key 都属于阻断缺陷。
- 可访问 `api.stepfun.com` 的演示网络。
- Windows 11 演示机和可用麦克风。
- StepAudio 的音频上传边界、数据条款、实时权限、延迟与限流；本地回退不阻塞黑客松。
- 四段 CSGO 受控素材与事件时间标注。
- 无隐私的测试桌面和下层点击测试应用。

### 9.2 需要尽早锁定但不阻断 Gate 0

- 弹幕引擎最终使用 `danmu.js` 适配还是本地轨道实现。
- StepAudio 的语言、延迟、限流、客户端资源、帧格式、心跳和会话边界。
- Windows 缩放比例演示基线（至少测试 100% 与 125%）。
- 若实现本地 ASR 回退，再锁定 Runtime/模型在 ASAR 外的路径和完整性校验。

## 10. 故障降级顺序

降级目标是保持用户可控和状态真实，而不是在任何情况下制造“仍然正常”的假象。

| 故障 | P0 行为 | 不允许的行为 |
| --- | --- | --- |
| 单个人格超时/无效 JSON | 丢弃本次、短退避、其他人格继续 | 阻塞所有人格或无限重试 |
| 人群导演失败 | 保持基础活跃人数，显示轻量降级 | 让导演直接生成替代弹幕或把并发拉满 |
| 连续 429 | 全局降并发、暂停环境烂梗、熔断后半开 | 32 路独立指数重试 |
| StepFun 不可用 | 停止上传、显示“AI 观众暂不可用”；弹幕层与控制仍可关闭 | 偷偷切换未知云服务或伪装实时 AI |
| ASR 失败 | 进入“仅根据画面回应”，保留重启/重选入口 | 把空转写当作主播沉默且不提示 |
| 麦克风断开 | 停止旧轨道，显式降级并重选 | 自动选择未经用户确认的新设备 |
| 捕获源关闭 | 取消相关模型任务，停止发图，要求重选 | 继续发送最后一帧假装直播进行中 |
| 弹幕引擎异常 | 保留控制窗，立即暂停/清屏，允许重建 Overlay | 影响捕获停止和凭据安全 |
| 恢复快捷键冲突 | 托盘与独立恢复窗仍可停止 | 只留一个无法使用的解锁入口 |

第一版不把本地随机烂梗当成云模型故障时的默认替代。若演示需要离线演示模式，必须在 UI 和证据中明确标记“演示回放/模拟数据”，不能与真实链路混淆。

## 11. 风险登记

| 风险 | 概率 | 影响 | 最早验证 | 缓解 |
| --- | --- | --- | --- | --- |
| StepFun 图片格式与手册假设不同 | 中 | 阻断 AI 主链路 | Gate 0 单图探针 | 用探针 Fixture 固定 Adapter，不在业务层扩散 Wire Schema |
| 实际并发低于 32 | 高 | 影响“满直播间”密度 | Gate 0 后阶梯 | 32 身份与活跃并发分离；导演批次调度；展示实际上限 |
| 2–4 个关键帧仍导致高延迟 | 中 | 回应过期 | Gate 0 多图探针 | 继续去重、缩放、降低关键帧数、TTL 丢弃 |
| StepAudio WebSocket 来不及稳定 | 中 | 语音互动缺失 | Day 1 前完成 Spike | 先验证官方实时路径，再探针同供应商 SSE 分段路径；失败则保留明确视觉降级但不能宣称完整体验 |
| Overlay 阻挡游戏点击 | 中 | 演示不可用 | Day 1 原生测试 | `setIgnoreMouseEvents`、三路恢复、中心点实际点击证据 |
| Overlay 被自己的截图捕获 | 中 | 自反馈刷屏 | Day 1 录屏验证 | 内容保护、源过滤、窗口标题/句柄过滤、循环检测 |
| 多人格输出撞车/晚到 | 高 | 屏幕混乱、语义过期 | Fake Scheduler 测试 | 每人格单在途、最新覆盖旧、TTL、全局密度控制 |
| 攻击性人格越线 | 中 | 安全与演示风险 | L0/L1 红线 Fixture | 不可关闭红线、分级、长度限制、屏蔽词和立即停止 |
| 停止后后台仍请求 | 中 | 隐私阻断 | Day 2 生命周期测试 | 会话代次、统一 Abort、零资源验收 |
| 打包后 StepAudio/媒体权限失败 | 中 | 开发机可用但 Demo 失败 | Day 3 打包 Smoke | 提前跑打包版本，验证麦克风权限、WebSocket origin、心跳、网络错误与干净配置 |

## 12. 正式演示脚本（约 8 分钟）

### 0:00–0:45 产品一句话与边界

- “这是一个个人 AI 假直播陪伴工具，不接真实直播平台。”
- 打开控制窗，展示无营销落地页，直接是可用的开播设置。

### 0:45–1:45 设置与隐私

- 选择受控 CSGO 回放窗口作为捕获来源。
- 选择目标显示器，强调捕获源与弹幕屏幕是独立概念。
- 选择麦克风并说一句测试语，展示真实电平和转写。
- 展示云端告知，主动勾选同意。

### 1:45–2:30 开始与点击穿透

- 开始假直播，弹幕层出现。
- 在弹幕覆盖区域点击下层测试按钮或游戏菜单，证明点击真实到达。
- 使用快捷键进入校准/解锁，再恢复穿透。

### 2:30–4:30 CSGO 四事件

- 播放单杀：出现少量惊讶、`?` 或质疑。
- 播放三杀：人群导演提升活跃人数，五秒内密度明显上升。
- 播放击杀后死亡：同时出现“可惜”和嘴硬吐槽。
- 播放零杀死亡：攻击性人格给出短促游戏语境吐槽，但不突破红线。
- 展示过期回应被丢弃，屏幕不在十几秒后突然补旧梗。

### 4:30–5:30 语音互动与人格差异

- 主播说：“刚才这波是不是很帅？”
- 至少一个人格引用问题回应。
- 同一事件展示新人友好、技术党、乐子人和喷子四种明显不同语气。

### 5:30–6:30 控制能力

- 调整速度、密度与显示区域。
- 屏蔽一个词或人格，证明立即生效。
- 执行清屏，说明 AI 仍在运行。
- 执行暂停，展示采集/麦克风/请求都归零；恢复只使用新上下文。

### 6:30–7:15 故障与降级

- 使用受控 Fake Server 或网络代理复现 429 Fixture。
- 展示全局活跃人数自动下降、没有重试风暴、控制窗仍可用。
- 明确这段是故障注入；不要声称故意压垮真实服务。

### 7:15–8:00 停止与诚实指标

- 点击停止，展示轨道、请求和队列计数为零。
- 展示当次实测的最大并发 N、P50/P95 和 30 分钟稳定性，而不是口头说“支持 32 并发”。
- 用一页后续路线收尾：多屏、手环协议、`+1` 插件、真实平台连接均为后续，不混入 P0。

## 13. 演示备用方案

备用方案用于抵御现场网络/游戏不稳定，但不能伪装成真实在线运行：

1. **首选**：受控 CSGO 回放 + 真实 StepFun + 真实麦克风。
2. **网络抖动**：展示最近一次完整真实证据视频，同时现场运行 Overlay/点击穿透/设备/停止；屏幕明确标注“真实运行录像”。
3. **StepFun 完全不可用**：演示协议 Fake Server 的降级能力，并单独展示此前的真实 API 探针证据；不能把 Fake 输出说成现场模型输出。
4. **游戏无法启动**：使用固定窗口播放素材，仍可证明采集、图片理解和事件弹幕。
5. **麦克风故障**：使用备用 USB 麦克风；若仍失败，只能声明语音链路未通过，不能播放预录音冒充现场麦克风。

## 14. Definition of Done

### 14.1 产品完成

- 控制窗可完成捕获源、目标屏幕、麦克风、人格和弹幕设置；扬声器为 P1。
- 用户同意后才能开始真实上传。
- 单屏无边框透明弹幕层可点击穿透并有可靠恢复路径。
- 四类 CSGO 事件和一条主播语音都能引出合理、短促、不同人格的反应。
- 用户能暂停、清屏、隐藏、恢复和停止，含义一致且状态真实。

### 14.2 技术完成

- Gate 0 文本/图片/SSE/取消/错误探针通过。
- 32 个身份配置可加载；至少 4 个独立人格真实端到端通过。
- 并发阶梯有保存的原始聚合证据和最大已验证 N。
- 全局 429、超时、坏 JSON、导演失败、设备断开均有可复现测试。
- 评论经过 Schema、安全、去重、TTL、密度和轨道控制。
- 停止后所有媒体轨道、SSE、任务和队列清零。

### 14.3 质量完成

- [09_TEST_AND_ACCEPTANCE.md](./09_TEST_AND_ACCEPTANCE.md) P0 项目全部通过。
- 30 分钟稳定运行无崩溃、无无界增长、无过期弹幕堆积。
- 事件到首条弹幕目标：P50 ≤ 2.5 秒，P95 ≤ 5 秒；未达到则如实展示实际值并判断是否阻断演示。
- 隐私与内容要求通过 [07_SECURITY_PRIVACY_CONTENT.md](./07_SECURITY_PRIVACY_CONTENT.md) 的发布门槛。
- Windows 打包构建在干净用户配置上走完一次完整演示。

### 14.4 文档与证据完成

- 每项声明能指向一次带版本、时间、配置和环境的运行证据。
- 证据包经过 Key、Base64、转写和隐私标题扫描。
- README/演示页不把 32 人格写成未经实测的 32 并发。
- 未完成项、降级项和外部未知项在演示结束页清楚列出。

## 15. 时间不足时的裁剪顺序

按以下顺序从 1 开始裁剪，不能跳过底层可信链路：

1. 装饰动画、头像、拟真在线人数。
2. 顶部/底部固定弹幕和复杂样式预设。
3. 高级正则屏蔽、丰富人格编辑器。
4. 真实人群导演模型。时间不足时可用实现同一 `CrowdDecision` 合同的受控规则 Detector 维持演示，但该构建只能标记为“导演降级”，不能宣称完整 P0；基础多人格仍必须真实。
5. 8/16/32 更高档并发；保留 1/4 阶梯和调度架构。
6. 20 秒窗口；保留真实多图和 10 秒或探针支持的最小有效窗口。

以下项目不能裁剪后仍宣称完成 P0：

- 真实图片 `step-explore` 请求和 SSE。
- 真实麦克风选择、转写与至少一次语音回应。
- 至少 4 个独立人格的真实端到端路径。
- 原生点击穿透与恢复路径。
- TTL、暂停、停止和资源清理。
- 云端告知同意、Key 隔离、日志脱敏。
- 可复现 CSGO 事件证明和诚实证据。
