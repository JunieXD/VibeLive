# FakeLive 产品需求文档（PRD）

> 状态：Greenfield v1 产品需求基线  
> 更新日期：2026-07-23  
> 目标平台：Windows 桌面  
> 目标交付：黑客松可运行原型，并保留演进为最终个人产品的边界  
> 产品定义：个人 AI 假直播陪伴 / AI 观众模拟娱乐工具

## 0. 文档范围与优先级

本文定义 FakeLive 第一阶段的功能范围、状态、用户流程、非功能要求和验收标准。它回答“第一版具体要做什么，以及怎样才算做成”。愿景和长期边界见 `01_PRODUCT_VISION.md`；技术实现、AI 协议、隐私细则和测试证据分别由本目录其他文档展开。

仓库旧 `docs/` 中描述的本地模型、竖向评论窗和其他历史方案已被本目录取代。实现冲突时按以下优先级处理：

1. 用户在当前项目中最新确认的决定。
2. `docs/from-scratch/` 下的产品与技术基线。
3. 明确记录且尚未被取代的决策。
4. 旧 `docs/` 仅作为历史参考。

需求优先级：

- **P0：** 黑客松端到端闭环不可缺少。
- **P1：** 从原型走向可日常使用的首个产品版本。
- **P2：** 明确延期的扩展能力。

## 1. 产品目标

### 1.1 P0 目标

1. 用户能在 Windows 上选择画面来源、麦克风和弹幕目标显示器；P1 再选择应用输出设备。
2. 用户明确同意云端处理后，开始一次个人假直播会话。
3. 系统按时间采样近期画面，并把主播麦克风语音转成带时间戳的文本。
4. 至少若干真实独立 AI 人格通过 `step-explore` 同时观察画面和主播讲话，并返回零至两条短弹幕。
5. 独立的人群导演识别普通场面和爆点，改变活跃人格数和展示密度，但不直接写最终弹幕。
6. 弹幕通过透明、置顶、点击穿透的屏幕层从右向左流动，不阻碍下方游戏操作。
7. CSGO 单杀、三杀、击杀后死亡、未击杀死亡能产生有区别的及时反应。
8. 用户能立即暂停、清屏、隐藏、恢复和停止；停止后不再采集、上传、生成或补发。
9. 个别模型失败、导演失败或 HTTP 429 不会冻结应用或触发 32 路独立重试风暴。
10. 团队能提供真实 API、并发、延迟、点击穿透、停止和隐私边界的验证证据。

### 1.2 P1 目标

- 完整提供约 32 个可编辑的会话内持久人格。
- 提供多个人格包、内容强度和更完整的过滤规则。
- 支持多显示器逐屏弹幕层与稳定的恢复机制。
- 提供长期稳定性、资源占用、错误诊断和可访问性能力。
- 允许用户将背景、主题和常用设备作为本地设置持久化。

### 1.3 非目标

- 不接入真实 Bilibili、虎牙或其他直播平台弹幕。
- 不做推流、公开直播间、观众账号、礼物、付费、关注和内容广场。
- 不伪造真实观众身份、平台在线人数或互动证据。
- 不做医疗、心理治疗或孤独症干预功能和宣传。
- 不承诺代替人类关系或专业支持。
- 不做摄像头与表情识别。
- 不在协议未知时做腕带专有接入。
- 不做完整 Bilibili 功能复刻。
- 不在黑客松阶段实现第三方插件市场或真实平台连接。

## 2. 已知事实、产品决定与待验证事项

### 2.1 已确认的产品决定

- 桌面平台为 Windows。
- AI 模型使用内部多模态 `step-explore`。
- API 使用 Anthropic Messages 风格的 `POST https://api.stepfun.com/v1/messages`。
- 使用 `x-api-key`、`anthropic-version: 2023-06-01`、顶层 `system` 和必填 `max_tokens`。
- 允许 `stream: true` 的 SSE；不得传 `thinking`；不得调用 OpenAI `/v1/chat/completions`。
- 目标人格库约 32 个，每个人格有独立调用流和独立会话内状态。
- 麦克风是完整产品体验的核心且首版必须接入。
- 弹幕为屏幕级横向弹幕，不是竖向聊天窗。
- 人群导演与人格生成分开。
- 用户可以选择自然冷场或持续热闹。
- 黑客松不接真实直播平台。

### 2.2 尚未验证，禁止写成事实

- `step-explore` 实际接受的图片内容块字段、MIME 类型和传输方式。
- 单请求图片数量、字节上限、上下文窗口和 10/20 张图片的可行性。
- 目标白名单的真实 RPM、并发上限、首 token 延迟和完整响应延迟。
- SSE 的全部事件类型、usage 字段、错误体和服务端重试提示。
- 32 路真实并发是否稳定。32 当前是人格和架构目标，必须通过 1/4/8/16/32 阶梯实测。
- StepFun 服务端是否保存、保存多久或如何使用请求中的截图和文本。条款未确认前不得承诺“不留存”。
- StepAudio WebSocket 实时音频帧格式、心跳、会话上限和限流细节。第一版固定由 `stepaudio-2.5-asr-stream` 生成文本，不依赖 `step-explore` 直接接收音频。
- 腕带通过标准 Windows 麦克风、Bluetooth GATT、串口还是厂商 SDK 接入。

## 3. 用户与权限角色

第一版只有一个本机用户角色：**主播/使用者**。

主播拥有以下权力：

- 决定采集哪个屏幕或窗口。
- 决定使用哪个麦克风和输出设备。
- 决定启用哪些 AI 人格及热闹程度。
- 查看云端连接和降级状态。
- 随时暂停采集、清除弹幕、隐藏弹幕、恢复或停止会话。
- 配置比硬性内容底线更严格的个人过滤规则。

AI 人格、人群导演和未来插件均不是权限主体，不能自行选择画面、改变硬上限、读取 API 密钥、执行系统命令或绕过用户停止操作。

## 5. 产品表面

### 5.1 首次使用与启动检查

首次使用流程承担隐私同意、设备可用性和恢复能力验证，不能用一页长说明代替真实检查。

#### FR-ONB-01 云端处理说明（P0）

开始按钮可用前，必须清楚展示：

- 选择的屏幕画面会被定期截取并发送到 StepFun 的 `step-explore` 服务。
- 麦克风语音会被处理为文本，并与近期画面共同作为 AI 上下文。
- 应用本地默认不持久保存原始截图；这不等于 StepFun 服务端不留存。
- 暂停或停止后相关上传何时停止。
- 内容可能包含其他人的消息、账号、工作资料或敏感信息，用户需选择合适的画面来源。

用户未明确同意前：

- 不得启动屏幕采集用于业务上传。
- 不得启动麦克风转写用于业务上传。
- 不得发送包含屏幕、语音转写或用户背景的模型请求。
- 可以进行不包含业务内容的连接健康检查，但 UI 必须区分健康检查与内容上传。

#### FR-ONB-02 API 连接检查（P0）

- 检查密钥是否存在且可由主进程安全访问。
- 用不含用户屏幕或语音的请求验证连接。
- 失败时显示可行动错误，不在日志或 UI 中展示完整密钥。
- 除一次性隔离 KeyEntry 中的用户当前输入外，不允许任何通用渲染进程读取或回显密钥。

#### FR-ONB-03 权限与设备检查（P0）

- 检查屏幕捕获、麦克风访问和全局快捷键是否可用。
- P0 枚举屏幕/窗口和麦克风；P1 增加输出设备。
- P0 允许用户查看真实麦克风电平；P1 增加输出测试音。
- 在 Windows 隐私权限被拒绝时给出明确恢复路径。

#### FR-ONB-04 恢复路径测试（P0）

- 首次开始前逐一实测固定全局快捷键、系统托盘命令和独立恢复窗。
- 任一路径注册或实测失败都不能进入完全穿透态；用户可以留在校准态修复或退出。
- 三条路径都由 Main 处理，不依赖 Overlay 自身可点击。

### 5.2 开播前控制台

#### FR-SET-01 画面来源（P0）

- 列出可捕获的显示器和应用窗口，并显示缩略预览。
- 明确区分“AI 观察的画面来源”和“弹幕展示的目标显示器”。
- 黑客松版本可以一次只观察一个来源、只显示到一个目标，但不能在 UI 中混为一个选择。
- 避免选择 FakeLive 自身窗口；如果用户选择到自身，应阻止开始或明确提示。
- 画面来源发生尺寸变化时，P0 重新计算采样与显示区域；P1 同时重新计算保护区坐标。

#### FR-SET-02 麦克风（P0）

- 枚举标准 Windows 麦克风设备。
- 选择后显示实时输入电平和静音状态。
- 提供短录音/回放或等价测试，证明实际采样来自选中的设备。
- 默认要求开始前有可用且已测试的麦克风；设备不可用或用户主动跳过时，可以在二次明确确认后进入`仅画面模式`。
- `仅画面模式`必须持续显示降级标记，且不能用于宣称语音互动 P0 已通过；正式验收仍必须使用真实麦克风。
- 会话中麦克风断开时可暂时进入视觉降级态，但必须提示重新选择，且不得继续复用旧转写。

#### FR-SET-03 输出设备（P1）

- 枚举标准 Windows 输出设备。
- 允许选择并播放测试音。
- 保存选择，供应用提示音或未来语音功能使用。
- 输出设备选择不代表采集系统音频。系统音频理解属于独立的延期能力。

#### FR-SET-04 用户背景（P0）

- 用户可输入称呼、当前游戏/内容和一段简短背景。
- 背景用于冷场梗和人格理解，不作为不可质疑的事实来源。
- 限制长度，并在请求和日志中按用户内容处理。

#### FR-SET-05 AI 观众（P0）

- 提供预制人格包和人格启用/禁用入口。
- 默认展示易懂的“基础热闹度”和“爆点上限”，而不是让普通用户直接配置 RPM。
- 高级设置允许用户选择“观察决策频率”（例如低/中/高或探针允许的 Hz）和每秒请求硬上限，并展示目标活跃人数、请求并发、超时与重试上限。
- 用户设置的是上限而不是服务保证；实际频率受画面变化、人格沉默、TTL、全局 429、服务配额和本机资源约束，只能自动降低，不能绕过已验证上限。
- 诊断同时显示“用户目标频率”和“最近 10 秒实际请求率”，避免把配置值冒充真实调用量。
- 开始前显示“已启用人格数”和“当前预计可同时活跃数”，不得把启用人数等同于真实并发。

#### FR-SET-06 冷场策略（P0）

提供二选一分段控制：

- **自然冷场：** 人格允许返回沉默，平静时可以没有弹幕。
- **持续热闹：** 人格在无明显事件时根据用户背景、主题和近期对话发少量环境梗。

持续热闹不能虚构未发生的击杀、高光、人物身份或平台事件。

#### FR-SET-07 弹幕校准（P0）

- 显示测试弹幕，用户无需真正调用 AI 即可校准。
- P0 设置滚动速度、显示面积和密度，并提供一套可读默认样式。
- P1 设置字号、颜色、描边、透明度、顶部/底部固定弹幕和一个或多个受保护矩形区域。
- 进入点击穿透前再次验证紧急解锁入口。

### 5.3 开始与会话控制

#### FR-LIVE-01 开始前置条件（P0）

只有以下条件满足时才可开始：

- 用户已经同意当前版本的云端处理说明。
- 有有效画面来源和目标显示器。
- 有可用且已测试的麦克风，或用户已经明确确认以`仅画面模式`降级开始。
- API 连接可用，或 UI 明确说明当前无法开始 AI 会话。
- 全局快捷键、托盘命令和独立恢复窗三条路径都已实测可用。
- 配置通过基本校验，基础热闹度不高于爆点上限。

点击开始后，不再弹出普通确认框；状态进入准备与启动阶段，并显示逐项进度。

#### FR-LIVE-02 实时状态（P0）

直播控制台至少显示：

- 会话时长。
- 画面来源状态与最后成功采样时间。
- 麦克风状态、实时电平与最后转写时间。
- `step-explore` 连接、有效活跃人格数、排队数和限流/退避状态。
- 人群导演状态与当前场面强度。
- 弹幕层状态：显示、隐藏、暂停或解锁。
- 当前降级原因和可行动的恢复入口。

状态用清晰文字和图标表达，不只依赖颜色。

#### FR-LIVE-03 暂停（P0）

暂停是隐私与资源动作，不只是停止动画：

- 立即停止新的屏幕采样和麦克风业务处理。
- 中止正在进行的模型 SSE 请求。
- 丢弃等待中的观察、候选和待展示弹幕。
- 屏幕上已有弹幕停止或清除，由一致的产品决定实现；P0 推荐停止并清屏，避免恢复后误解旧内容。
- 恢复时只能使用恢复之后的新上下文，不补发暂停前结果。

#### FR-LIVE-04 清屏（P0）

- 立即移除当前可见和已排期的弹幕。
- 不停止画面、麦克风或 AI 会话。
- 清屏后的旧候选不得再次进入展示队列。

#### FR-LIVE-05 隐藏弹幕（P0）

- 关闭屏幕弹幕的可见性，但会话和 AI 处理可以继续。
- 隐藏期间产生的弹幕不积压、不在恢复显示时集中补发。
- 控制台继续显示系统状态，不把“隐藏”显示成“暂停”。

#### FR-LIVE-06 停止（P0）

- 单次动作立即进入停止流程，不弹出会拖延紧急中止的确认框。
- 停止所有屏幕和麦克风轨道。
- 中止全部人格、导演和语音识别中的请求。
- 清空帧引用、转写、观察、候选和展示队列。
- 关闭或隐藏弹幕层并释放置顶/穿透状态。
- 所有迟到响应必须因会话代次不匹配而丢弃。
- 1 秒内进入可证明的已停止状态；若某资源尚未释放，显示具体阻塞项而不是假装结束。

#### FR-LIVE-07 紧急解锁（P0）

- 全局快捷键立即使弹幕层退出点击穿透或唤回独立控制入口。
- 托盘和独立控制窗口提供相同入口。
- 解锁只改变交互模式，不应偷偷继续覆盖用户点击。
- 重新进入穿透态必须由用户明确操作。

## 6. 感知与上下文需求

### 6.1 视觉观察窗口

#### FR-CTX-01 近期画面（P0）

- 产品设置提供 10 秒和 20 秒两档观察窗口。
- 目标语义为每秒约一个代表性画面，即约 10 或 20 个时间点。
- 实际发送的图片数量、格式、压缩、分辨率和选择策略必须由真实 API 探针决定；在未验证前不能硬编码对外承诺“每次必发 20 张原图”。
- 每个画面带捕获时间、来源尺寸和会话 ID。
- 帧缓冲有界，超出窗口或请求失效后立即释放。
- 可以跳过几乎相同的帧，但不得因此破坏击杀到死亡等连续事件理解。

#### FR-CTX-02 自身排除（P0）

- FakeLive 控制窗、弹幕层和恢复窗不得被重新作为业务画面送给模型。
- 需要通过真实捕获结果证明，而不是只验证调用了窗口保护 API。
- 如果当前平台组合无法完全保证排除，必须警告用户并避免选择包含自身的来源。

### 6.2 麦克风与转写

#### FR-CTX-03 StepAudio 句界与时间戳（P0）

- 默认使用 StepAudio `server_vad` 判断语音开始和结束；麦克风开启时音频分片仍在持续上传，界面必须如实显示。
- 转写片段包含开始、结束时间和稳定/临时状态。
- 人格只接收与当前观察窗口相关的近期稳定文本。
- 不把设备噪音或空白当作主播发言。

#### FR-CTX-04 说话回应（P0）

- 每次人格决定可引用、质疑、回答或忽略主播近期讲话。
- 回复必须短，不生成长篇助理式答案。
- 对画面和语音冲突时允许表达不确定，不应把低置信度判断包装成事实。

### 6.3 观察快照

每次送给人格的逻辑观察至少包含：

- 会话 ID、观察时间和展示截止时间。
- 经过选择的近期画面引用。
- 近期主播转写。
- 用户背景和当前主题。
- 该人格配置及自身会话内短期历史。
- 精简后的近期公开弹幕上下文。
- 当前冷场策略。

观察快照不得包含其他人格的私有历史或 API 密钥。

## 7. AI 观众需求

### 7.1 人格模型

#### FR-AI-01 约 32 个会话内持久人格（P0/P1）

- 数据层可装载约 32 个稳定 ID 的人格资料。
- 每个人格至少定义：显示名、原型、立场、说话风格、偏好事件、忌讳、沉默倾向、爆发倾向、重复倾向和内容强度。
- 人格在一次直播会话内保持身份、语气和短期历史稳定。
- P0 必须用至少若干真实独立人格跑通端到端；P1 补齐完整 32 人格日常可用性。
- 不能用一次模型调用批量生成 32 个角色的内容，再声称是“32 个独立人格调用”。
- 不能把启用 32 份配置或创建 32 个 Promise 等同于真实 32 路模型会话。

#### FR-AI-02 独立调用与归属（P0）

- 每个启用人格拥有独立请求流和独立短期状态。
- 每个人格同一时间最多一个在途请求；出现更新观察时只保留最新待处理观察。
- 返回结果必须携带会话 ID、人格 ID、观察时间和截止时间。
- 乱序完成不能导致人格错配。
- 一个人格的失败不得停止其他人格。

#### FR-AI-03 输出协议（P0）

每次人格决定只能是：

- 沉默；或
- 一条短弹幕；或
- 两条有明确顺序的短弹幕。

模型返回需要经过运行时结构校验、长度限制、内容过滤、去重和过期检查。模型不拥有调用工具、执行代码、改变并发或直接操作弹幕层的权力。

#### FR-AI-04 人格差异（P0）

给定同一段 CSGO 画面：

- 质疑型人格可能发问号或怀疑开挂。
- 乐子人人格更偏向梗和夸张短句。
- 技术型人格更偏向走位、准星或换人价值。
- 新人友好人格解释发生了什么。
- 护主播人格反驳负面弹幕。
- 潜水人格只在爆点出现。

差异应来自角色数据和独立历史，不靠在名字前机械加前缀。

### 7.2 `step-explore` 客户端行为

#### FR-AI-05 协议（P0）

- 仅调用 `/v1/messages`。
- `model` 为 `step-explore`。
- 使用顶层 `system` 和 Anthropic `user`/`assistant` 消息。
- `max_tokens` 必填，输出上限应与一至两条短弹幕相称。
- 使用 SSE 时支持逐事件解析、超时和主动取消。
- 不发送 `thinking`。
- 不使用 `/v1/chat/completions`。

图片请求体必须先由已认证探针验证，再固化到客户端适配器。未经验证的示例不能作为生产契约。

#### FR-AI-06 全局限流（P0）

- 对所有人格和导演统一调度请求压力。
- 遇到 429 时采用有上限、带随机抖动的指数退避，并在可用时尊重服务端提示。
- 降低有效活跃人数，暂停低优先级环境梗，优先保留新鲜高光。
- 不允许 32 个人格各自独立立即重试。
- 连续失败时进入冷却和半开探测，UI 显示当前有效人数。

### 7.3 人群导演

#### FR-DIR-01 导演职责（P0）

人群导演只返回：

- 场面强度：平静、普通、爆点。
- 可能的事件键和置信度。
- 建议活跃人格数。
- 爆发持续时间和截止时间。

导演不直接写最终弹幕，不得超过用户设定的爆点上限。

#### FR-DIR-02 事件与防重触发（P0）

首个事件集合：

- 单次击杀。
- 多杀/三杀。
- 击杀后死亡。
- 未击杀死亡。
- 可选的回合结果或低置信度高光。

同一事件只能触发一次主要爆发。低置信度时可以增加少量好奇、问号或观望人格，不应明确断言“三杀”“开挂”等事实。

#### FR-DIR-03 导演降级（P0）

- 导演失败时维持基础热闹度。
- 不因导演失败停止人格和弹幕层。
- 控制台显示“人群导演暂不可用，当前保持基础热闹度”。

## 8. 弹幕需求

### 8.1 窗口行为

#### FR-DMK-01 屏幕层（P0）

- 对目标显示器创建透明、无边框、置顶、任务栏隐藏的窗口。
- 直播态默认点击穿透。
- 黑客松可只支持一个目标显示器；P1 按显示器创建独立弹幕层。
- 画面缩放、DPI 或分辨率变化时重新布局，不产生永久偏移。
- 屏幕层只接收通过校验的展示命令，不接触 API 密钥和原始音频。

#### FR-DMK-02 弹幕类型（P0 / P1）

- P0：从右向左滚动。
- P1：顶部固定、底部固定及三类独立开关。
- P0 不要求图片弹幕、礼物、头像或复杂富文本。

### 8.2 轨道与密度

#### FR-DMK-03 轨道防碰撞（P0）

- 每条滚动弹幕占用一条可计算轨道。
- 新弹幕不能在同轨追上尚未留出安全距离的旧弹幕。
- 没有安全轨道时，按优先级等待短暂时间或丢弃低优先级弹幕，不强行叠放。
- 正常密度下文字应可读；爆点允许更密但仍受硬性屏幕上限控制。

#### FR-DMK-04 过期与去重（P0）

- 每条候选弹幕都有 `createdAt`、`showAt` 和 `expiresAt`。
- 到展示时间已过期则丢弃。
- P0 对完全相同的在途/待显示命令做基础抑制；P1 增加可调的近似重复合并。爆点跟风人格可在受控规则下重复问号、`+1` 等短反应。
- 隐藏、暂停、清屏和停止均使相关旧队列失效。

#### FR-DMK-05 设置（P0 / P1）

P0 用户可调整：

- 滚动速度。
- 基础密度和爆点密度上限。
- 可用屏幕高度百分比。

P1 增加：字号、颜色、描边、透明度、顶部/底部/滚动类型开关和矩形受保护区域。

设置变化应在不重启会话的情况下预览或生效。

### 8.3 内容过滤

#### FR-DMK-06 用户过滤（P0 / P1）

- P0：人格启用/禁用、语言强度档位、单条长度上限、单人格短时频率上限和最终安全过滤。
- P1：用户关键词/短语屏蔽表、近似重复阈值和按人格/风格过滤。

#### FR-DMK-07 不可关闭的安全底线（P0）

无论人格风格和用户设置如何，最终展示前都必须阻止：

- 真实威胁、鼓励现实伤害。
- 针对受保护身份的仇恨。
- 鼓励自残或自杀。
- 私人凭据、住址等敏感信息的泄露或诱导。
- 涉及未成年人的性内容。
- 冒充具体真实个人、真实平台账号或真实付费互动。

## 9. 状态模型

### 9.1 会话主状态

```text
启动检查
  -> 待设置
  -> 可开播
  -> 准备中
  -> 直播中
  -> 已暂停
  -> 直播中
  -> 停止中
  -> 已结束
```

`降级`不是替代所有主状态的单独页面，而是附着在“直播中”或“已暂停”上的明确标记，例如：

- 画面来源断开。
- 麦克风断开，暂时仅根据画面回应。
- AI 请求限流，有效人格数降低。
- 人群导演不可用，维持基础热闹度。
- 弹幕层不可用，但控制和停止仍可用。

### 9.2 弹幕层状态

```text
未创建
  -> 校准态
  -> 穿透显示态
  -> 暂停态 / 隐藏态 / 紧急解锁态
  -> 穿透显示态
  -> 已关闭
```

- “暂停”影响采集和生成。
- “隐藏”只影响可见性，不积压待补发弹幕。
- “紧急解锁”改变点击行为并暴露控制入口。
- “清屏”是动作，不是持久状态。

### 9.3 人格状态

```text
空闲 -> 排队 -> 流式响应 -> 校验 -> 空闲
                               -> 退避
                               -> 隔离
```

- 每个人格最多一个在途请求。
- 新观察替代旧的待处理观察。
- 退出会话后所有状态与短期历史失效，除非未来明确设计跨会话记忆。

## 10. 错误与降级需求

| 故障 | 必须行为 | 用户可见文案方向 |
| --- | --- | --- |
| 画面来源关闭或断开 | 停止发送截图；取消依赖旧画面的请求；要求重选 | 画面来源已断开，已停止发送截图 |
| 麦克风断开 | 停止旧音频和转写；暂时视觉降级；提供重选 | 麦克风已断开，当前仅根据画面回应 |
| 个别人格超时/结构错误 | 丢弃该结果；该人格退避；其他人格继续 | 不必逐条打扰用户，状态区汇总 |
| 大量 429 | 全局降并发、暂停环境梗、冷却后试探恢复 | 请求过快，AI 观众已自动减少到 N 位 |
| 人群导演失败 | 使用基础热闹度，不阻塞弹幕 | 人群导演暂不可用，当前保持基础热闹度 |
| `step-explore` 整体不可用 | 停止新的云端上传；中止请求；明确离线/不可用 | AI 服务暂不可用，已停止发送新内容 |
| 弹幕层崩溃 | 控制窗和停止仍可用；尝试重建；不积压弹幕 | 弹幕显示已中断，AI 生成已暂停或降级 |
| 输出内容过期 | 静默丢弃，不补发 | 无需逐条提示，计入诊断指标 |

黑客松版本不需要为了“看起来在线”而默认启用随机本地弹幕回退。上下文 AI 不可用时应诚实停止相关生成；未来可提供用户明确选择的本地环境梗模式。

## 11. 非功能需求

### 11.1 延迟与时效

以下为设计目标，必须由真实端到端测量证明：

- 事件到首条相关弹幕：P50 不高于 2.5 秒，P95 不高于 5 秒。
- 暂停、清屏、隐藏：用户动作后 500 毫秒内可见生效。
- 停止：1 秒内终止业务采集、新请求和展示队列。
- 任何超过事件截止时间的响应不再展示。

### 11.2 稳定性

- 所有帧、转写、请求、候选和弹幕队列有界。
- 单人格、导演、转写或弹幕层失败不拖死整个主进程。
- 30 分钟演示会话无持续队列增长、无明显内存泄漏、无无法停止的资源。
- 关闭或停止后网络请求、媒体轨道和定时器数量回到基线。

### 11.3 资源控制

- 截图按观察需求缩放压缩，避免保存桌面原分辨率的无限帧序列。
- 同一人格只有一个在途请求。
- 降级优先丢弃过期与低优先级环境梗，不堆积等待。
- 控制台应显示有效活跃人数，避免目标配置掩盖实际限流。

### 11.4 可访问性

- 所有关键状态不只使用颜色表达。
- 控制窗口可使用键盘完成开始、暂停、清屏、隐藏和停止。
- 提供减弱动态效果模式，降低滚动速度或改用顶部/底部固定形式。
- 屏幕阅读器不应逐条朗读高速实时弹幕；P1 可提供独立的近期弹幕列表。
- 文本在 Windows 常见缩放比例下不溢出设置控件。

### 11.5 可观测性

诊断信息应包含：

- 会话 ID、匿名人格 ID、观察时间、请求阶段、状态码、退避状态、延迟和丢弃原因。
- 不记录 API 密钥、完整请求头、原始图片 Base64、原始音频或默认完整转写。
- 错误日志可导出前必须自动脱敏。

## 12. 隐私与凭据要求

### 12.1 数据最小化

- 只捕获用户明确选择的来源。
- 只保留当前 10/20 秒窗口及在途请求所需帧。
- 本地默认不持久保存原始截图和原始麦克风音频。
- 转写和人格短期历史默认限于当前会话。
- 选定窗口关闭、暂停或停止后，立即停止相关数据进入新请求。

### 12.2 云端透明度

- 开始前明确说明屏幕和转写将发送到 `step-explore`。
- 直播中持续显示云端活动状态。
- 未知的服务端保留行为明确标记“待服务条款确认”，不能以本地不保存代替云端承诺。
- 公开演示时使用经过同意且脱敏的画面和语音素材。

### 12.3 API 密钥

- 由 Electron 主进程安全存储和访问。
- 不进入渲染进程、人格数据、截图、测试固定夹具或 Git 仓库。
- 日志、错误弹窗和网络导出中全部脱敏。

### 14.1 启动与设备

### 14.2 真实 AI 链路

- [ ] `/v1/messages` 文本请求真实成功。
- [ ] 使用经过探针验证的图片内容块完成真实多模态请求。

- [ ] 两个人格在同一观察下表现出不同语气或触发选择。
- [ ] 沉默、一条弹幕和两条连续弹幕三种决定均有测试。
- [ ] 人格乱序返回不会错配显示名或历史。
- [ ] 1/4/8/16/32 并发阶梯结果被保存；UI 宣称不超过真实证据。

### 14.3 CSGO 场景

- [ ] 单杀产生至少一条相关反应。
- [ ] 三杀后 5 秒内的有效弹幕密度明显高于单杀。
- [ ] 击杀后死亡产生混合的肯定/惋惜/战术反应。
- [ ] 未击杀死亡可产生与人格匹配的吐槽、叹气或建议。
- [ ] 主播说话至少被一个人格正确引用、回答或接梗。
- [ ] 同一事件不会反复触发完整爆点。
- [ ] 迟于截止时间的反应不会出现在屏幕上。

### 14.4 弹幕与原生交互

- [ ] P0 滚动弹幕从右向左移动；P1 顶部和底部固定弹幕可用。
- [ ] 正常密度下同轨弹幕不会追撞到不可读。
- [ ] P0 速度、密度和显示区域设置有可见效果；P1 字号、颜色、描边和透明度设置有可见效果。
- [ ] P0 弹幕不超出所选显示区域；P1 启用保护区后，受保护区域不会被弹幕覆盖。
- [ ] 真实鼠标点击能穿过弹幕层操作下方游戏/测试应用。
- [ ] 点击穿透由目标位置的原生/桌面交互证明，不能只使用 Playwright locator `click()`。
- [ ] 全局快捷键、托盘和独立恢复窗三条路径在弹幕穿透态下均可用。
- [ ] 实际捕获画面不包含 FakeLive 自身弹幕和控制窗。

### 14.5 控制、降级与停止

- [ ] 清屏在 500 毫秒内移除可见和排期弹幕，但会话继续。
- [ ] 隐藏期间不积压恢复后补发的弹幕。
- [ ] 暂停停止采集、新请求和队列，并取消在途请求。
- [ ] 停止后 1 秒内没有活跃媒体轨道、新模型请求和待展示队列。
- [ ] 个别人格失败时其他人格继续工作。
- [ ] 导演失败时回退基础热闹度。
- [ ] 模拟 429 时请求压力全局下降，没有 32 路同步重试。
- [ ] 画面或麦克风断开后不继续使用旧上下文。
- [ ] `step-explore` 整体不可用时停止发送新业务内容并显示明确状态。

### 14.6 证据包

每次候选发布至少保留：

- 运行清单：版本、提交、机器、Windows 版本、设备和关键设置。
- 事件时间线：采样、转写、请求、首 token、完成、校验、展示和丢弃。
- 已脱敏 API 探针结果。
- 并发阶梯表与延迟 P50/P95。
- 429/超时/部分 SSE/5xx 故障注入结果。
- 点击穿透、自身排除、暂停/停止的截图或录屏。
- 停止前后媒体轨道、请求、队列和临时文件差异。
- 30 分钟稳定运行的内存、队列和错误摘要。

## 15. 产品成功标准与发布门槛

黑客松原型可以被判定为“端到端成立”，仅当：

1. 真实屏幕与真实麦克风上下文进入真实 `step-explore` 调用。
2. 至少 4 个独立人格真实生成短弹幕，且没有把 32 份配置误称为 32 路实并发。
3. 四类 CSGO 固定场景能复现差异化反应和密度变化。
4. 弹幕在原生透明置顶窗口中真实点击穿透，并能紧急恢复。
5. 暂停和停止从资源层生效，而不只是 UI 文案变化。
6. 429 和失败路径不会造成无限重试、队列增长或错误补发。
7. 未同意前零业务内容上传，密钥和原始媒体不进入日志。
8. 所有未验证事实仍被标记为未验证，没有用目标值替代测试证据。

若真实并发只稳定到 4、8 或 16，仍可交付诚实的原型，但必须在演示界面、报告和口头说明中显示实际值，并把 32 保留为明确的扩展目标。

## 16. 风险与依赖

| 依赖/风险 | 当前状态 | 对 P0 的影响 | 处理方式 |
| --- | --- | --- | --- |
| `step-explore` 白名单与 API 密钥 | 外部前置 | 无法做真实链路则不能完成核心验收 | 最先完成连接和图片/SSE 探针 |
| 图片内容块与负载上限未知 | 未验证 | 影响关键帧质量与延迟 | 已定默认 2–4 个关键帧；探针校准压缩、分辨率和安全上限 |
| 并发/RPM 未知 | 未验证 | 影响 32 人群效果 | 阶梯压测，全局调度，诚实降级 |
| StepAudio 实时 ASR 延迟与协议细节 | 模型已选、能力待探针 | 影响主播说话回应 | WebSocket Adapter，固定短语与断流端到端测试 |
| Windows 点击穿透和自身排除 | 需实机验证 | 直接影响可用性与递归画面 | 原生交互测试和真实捕获证据 |
| CSGO 事件理解不稳定 | 模型能力风险 | 影响首个演示 | 固定样本、置信度、过期和保守导演 |
| 毒舌人格体验过强 | 产品安全风险 | 可能伤害用户或破坏陪伴感 | 默认混合人格、强度控制、硬底线和一键停用 |
| 云端数据保留未知 | 政策风险 | 影响隐私文案和公开发布 | 获取正式条款；未知前不做无留存承诺 |

## 17. 待决策但不阻塞文档落地的问题

这些问题进入决策日志，在实现前或探针后收敛：

1. 暂停时屏幕上已有弹幕是冻结还是立即清除；P0 推荐立即清除。
2. `step-explore` 图片内容块、压缩、图片数量和分辨率的最终契约。
3. StepAudio 实时帧编码、会话时长、限流和数据处理条款的真实探针结果。
4. 黑客松演示账户能够稳定达到的最大真实并发。
5. 一条弹幕的默认最大字符数和不同语言的计量规则。
6. AI 来源说明在屏幕弹幕层中的最小呈现形式；无论形式如何，都不能伪造真实平台身份。
7. P1 保护区先实现单矩形拖拽，还是直接支持多个命名区域。
8. 输出设备在首版除测试音外是否承担任何提示音。
9. StepFun 正式数据保留、使用和删除条款。

## 18. 变更控制

以下变更视为产品范围变化，不能在实现中静默发生，必须更新文档和决策记录：

- 将独立人格调用改为一次批量生成。
- 将麦克风从 P0 核心输入移除。
- 将屏幕级点击穿透弹幕改回竖向评论窗。
- 接入真实直播平台或制造真实平台身份/指标。
- 将云端模型改回完全本地模型，或更换 `step-explore` 主模型。
- 将 32 从人格目标写成未经测试的并发保证。
- 开始持久保存原始截图、音频或跨会话人格历史。
- 开放硬性安全底线的关闭选项。
- 引入腕带专有协议、系统音频或第三方插件执行能力。
